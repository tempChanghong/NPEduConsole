# 学校管理网页迁移清单

## 学校管理总览与待办

学校管理员选择学校后进入「学校总览」，也可从左栏随时返回。「管理待办」按当前启用学期列出学校配置、具体班级和具体大屏。建年级、单班或批量开班沿用「新建行政班」。对未登记首屏的班级，点击「前往登记」进入原登记区，再由管理员确认登记。对待接入或待上报的大屏，点击「定位大屏」按原班级和绑定 ID 打开对应入口。返回总览时重新读取学校服务。

「大屏状态」分别显示网页首次登录和值守心跳，以及 NPEduTools 配对和有效上报。Console 登记首屏后会出现 NPEduTools 接入待办，登记网页账号也会独立显示首次登录待办。终端成功上报后，同一绑定的首次上报待办消除。KV 保留最近一次有效上报的时间，终端重开 Host 会话仍可查阅该记录。旧数据若已在升级前丢失上报证据，显示「待核对」。原班重新启用后，既有规则判定旧 NPEduTools 授权已失效时，待办提示现场重新配对。

教师职责、走班任课、教师账号、网页大屏和学期启用仍打开原网页学校管理对应入口。网页地址取自 KV 的 `FRONTEND_URL`。地址未配置时，Console 显示原网页办理提示。无需另填监控凭据。

上线先部署 KV 并应用迁移 `20261121040000_npep_device_last_report`，再更新 Console 和网页。旧网页仍可查询指定学期。新接口位于 `/api/v2/admin/schools/:schoolId/management-overview/current`。

## 当前学期行政班任课

在「学校总览 → 管理待办」找到某班某科缺任课教师，点「分配任课」。也可在启用的班级详情点「任课分配」，选择随行政班授课的科目，查看、修改或移除已有关系。

新增时选择本校已有教师及主讲或协同身份，可以同时勾选同年级、该科目随行政班授课的其他启用班级。预览列出逐班变化和当前安排。有主讲冲突或预览已过期时，整批不写入。可以取消有冲突的班、选择协同，或单独修改原关系。提交回包中断时，Console 先只读核对服务器当前安排。返回总览后重新读取待办。

新增或调整任课可能授予或提升班级成员权限。修改为协同或移除任课时，已有班级成员权限保留，其他科目和职责授予的访问照常有效。人员账号、班主任及年级职责、走班任课仍从原网页办理。上线先更新 KV，再更新 Console，本轮无新增数据库迁移。

本地联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --current-teaching`。使用隔离数据库、Windows Console 和 Edge，截图默认写入 `.artifacts/current-teaching/desktop-live`。

## 学校审计记录的退役条件

使用本地学校管理账号登录 NPEduConsole，选择学校后即可查看审计记录。即使学校尚无启用学期、班级或大屏，也可以查阅。该入口读取 KV 的学校 `AuditLog`。每次查询时，KV 都会核对当前账号在该校的 OWNER 或 ADMIN 权限。

| 管理员要做的事 | Console 中的对应操作 |
| --- | --- |
| 找出某天失败的操作 | 选择操作来源、类型、结果及本地起止日期，读取选中日期全天的记录。 |
| 查更早的记录 | 按时间倒序浏览，点击「加载更多」查看下一页。点击「刷新」或「应用筛选」都会从第一页开始。 |
| 核对一条记录 | 查看操作者或大屏、时间、操作对象、请求路径、HTTP 状态、来源 IP 和脱敏参数。旧记录缺少的字段按缺失显示。 |

**网页入口目前保留。** 网页提供 OAuth 登录，桌面端目前使用本地学校管理账号。部署新版 KV 和 Console 后，先确认使用该入口的管理员均有可用的桌面登录方式，再移除 `section=audit` 的网页导航并处理指向旧地址的链接。只持有 OAuth 身份的管理员在此之前可以继续使用原网页，无需为本轮迁移额外设置口令。

## 当前学期的行政班学生名单

使用本地学校管理账号选择一个行政班后，打开「学生名单」。可逐行增改、移出和排序，也可粘贴 Excel 两列或纯文本名单，选择追加或替换。确认前会列出相对于学校原名单的变化。无大屏的班级也可以办理。

有学号的行按学号匹配，保留前导零。无学号的行按未编号学生的姓名匹配，遇到同名需要逐行核对。改名或改学号可直接编辑现有行，以保留学生 ID。移出学生后，已登记的历史考勤仍保留原 ID。

管理员和大屏共用同一份名单修订号。遇到并发修改，Console 保留草稿，读取当前名单供核对。保存回包中断时也会先读取服务器现状。新版 KV 会在写入时检查本班学期是否仍在使用，切换学期后需重新选择班级。

网页版仍承接 OAuth 管理账号和指定其他学期的名单维护。退役该入口前，需确认这两类使用场景都有可用的入口。

## 建年级并开班

管理员选择学校后，点击「新建行政班」。当前启用学期没有年级，或需要补建年级时，在同一个窗口点击「新建年级」，填写名称和代码。Console 收到本次创建回执并刷新年级后自动选中对应年级。可继续填写班名和代码，按需调整「允许学生自行选择此行政班」。年级代码在学期内唯一，班级代码在该学期的教学空间中唯一。

年级重码时可更换代码。创建回包中断后点击「核对结果」，Console 按原请求编号查询。学校暂未记录该请求时，可用原编号重试。另一个管理员创建的同名或同码年级不会被自动选中。填写期间切换学期时，需刷新并核对后再提交。

点击「创建并录入名单」后，Console 按 KV 返回的班级 ID 定位新班，打开学生名单。建班和名单保存分两步生效，关闭名单窗口后，已创建的班级仍可从班级列表进入。建班回包中断时，「重试确认」沿用原请求，KV 返回首次成功的班级 ID。切换学期或失去学校管理权限后，旧表单无法再写入。

升级 KV 时需应用 `20261121000000_admin_class_creation` 和 `20261121020000_current_grade_creation` 数据库迁移。它们保存建班和建年级的原请求回执。

## 修改当前学期的年级名称

选择学校并打开「新建行政班」。在「所属年级」选中目标年级，点击「修改名称」。保存后仍选中这个年级，可以随时关闭窗口。已有班级和名单的年级也能改名。年级 ID、代码、排序、所属学期以及班级和学生关联保持原样。

多人编辑发生冲突时，Console 保留输入并显示学校的最新名称。回包中断时先读取该年级，提示学校当前名称是否与本次输入一致。启用学期变更后，需重新载入并选择年级。改名入口需要新版 KV 的年级版本字段和当前学期改名接口，无需新增数据库迁移。网页继续承接指定其他学期的新建与编辑、年级代码及排序调整和 OAuth 管理员。

## 按年级批量开班

选择学校并打开「新建行政班」。在「所属年级」选中已有年级，再点击「批量开班」。输入起止编号和可调整的名称、代码前缀，例如用高一年级生成 1 至 12 班。点击「生成预览」，可逐行修改名称、代码及学生自选设置；一次可创建 1 至 100 个班。

点击「核对」可提前查看代码冲突。保存时 KV 重新确认学校权限、启用学期、目标年级和代码占用。冲突会标到相应行并保留草稿，整批成功或整批不建班。回包丢失时点击「核对结果」，Console 按原批次编号查询管理员自己的回执。在同一次登录中关闭建班窗口后，重新打开可继续核对。若服务器暂未记录，可用同一编号重试未改动的草稿。

成功后任选一条服务器回执打开名单。Console 重新启动后，班级也可从常规班级列表找到。上线前需应用 KV 的 `20261121030000_current_class_batch_creation` 迁移。旧网页仍可为指定学期批量建班。

## 当前学期行政班维护

选择学校和班级，在班级详情点「维护班级」。可以修改名称、代码和学生自选设置。代码在同一学期的教学空间内唯一。版本冲突时，先点「核对服务器班级」，查看服务器名称、代码和状态，再决定是否保存保留的草稿。保存并刷新后，Console 按原班级 ID 选中该班。

点「查看停用影响」，核对学生、大屏、任课及正在生效的作业或通知等关联。读取失败时可以重试。KV 会在写入时核对当前启用学期、权限、班级版本和预览的关联内容；关联变化后，必须以新摘要为准再次确认。停用后在侧栏勾选「已停用」，选中原班并点「重新启用」。重新启用会回到正常列表并选中原班，原名单、大屏绑定和历史发布记录仍对应原 ID。

停用期间，现有网页大屏访问该班会被 KV 拒绝。重新启用后，未过期、未另行重置的原网页大屏令牌可继续使用。NPEduTools 按既有数据库规则处理：停用会推进大屏绑定版本，并使旧设备配对授权失效。重新启用保留原大屏与设备历史记录，教室端需重新配对。旧网页仍可管理指定学期。本次升级需要部署支持行政班维护接口的 KV 和 Console，无新增数据库迁移。

## 给新班准备第一台教室大屏

在「教室设备」选中当前学期的新班，点击「准备教室大屏」。收到登记确认后，Console 会按返回的大屏 ID 打开「配置口令接入」。本班已设管理口令时可直接沿用。首次设置时，在此预设班级管理口令并确认开放。现场在 NPEduTools 的「学校互联」选择对应学校、班级和大屏，输入班级管理口令。终端上报后，管理员刷新即可看到设备。

登记成功后可以稍后开放接入。若登记回包中断，先刷新列表核对；有停用大屏的班级需先在原管理入口核对记录。网页大屏登录账号和 PIN 仍走原网页流程。

## 十三个旧入口的去向

| 旧网页入口 | 已有桌面能力或仍需网页完成的业务 |
| --- | --- |
| 审计记录 | 本地学校管理账号可在 Console 完成上述查询。 |
| 管理总览 | Console 选中学校后显示当前学期诊断和管理待办。需由网页办理的事项仍链接到原入口。 |
| 组织与班级 | Console 可在当前启用学期新建年级、修改年级名称、单个或按已有年级批量新建班级、编辑班级资料、核对影响后停用、重新启用及录入名单。其他学期的管理、年级代码和排序、学科及教学关系仍在网页。 |
| 学生名单 | Console 可维护当前学期一个行政班的名单，支持批量粘贴、差异预览、保存及冲突核对。 |
| 教师分配 | Console 可新增、批量分配、修改和移除当前学期随行政班授课的任课。教师职责、走班任课和作业快捷输入配置仍在网页。 |
| 大屏设备 | Console 可为新班登记首台 NPEduTools 大屏并查看连接状态。创建或重置网页大屏账号、维护作业快捷截止时间仍在网页。 |
| 大屏互联 | Console 已覆盖部分班级接入、麦克风策略和软件维护。设备撤销、考试控制等仍有网页入口。 |
| 自习监测 | Console 可为单班增加自习安排、查看回执和场次。年级策略、完整日历、照片等仍需网页。 |
| 自习座位表 | 座位安排仍在网页。 |
| 账号与管理员 | 本地账号、管理员及身份分配仍在网页。 |
| 高级批量导入 | 组织导入的校验、预览和写入仍在网页。 |
| 服务器迁移 | 学校迁移包导出等操作仍在网页，与 KV 自动备份状态分别管理。 |
| 学期运维 | 建立学期草稿、启用检查及切换学期仍在网页。 |

教室端可在 NPEduTools 首次设置或学校互联设置中使用快速列表。目标大屏未列出时，按学校和班级的完整名称或代码查找。一个班有多台大屏时可翻页选择，随后按原流程提交申请或输入班级管理口令。精确查找需要 KV 和教室端均支持该功能。

node tests/live-kv.mjs 'D:/CodeProjects/NPClassworksKV' 'C:/Program Files/PostgreSQL/17/bin' --grade-creation

名单联调会停用夹具中的 NPEP，检查无设备班级、同名学生、屏幕并发写入、学期切换、历史考勤和保存结果核对。网页名单的行为可参照 NPClassworks 的 `src/components/admin/ClassRosterManager.vue` 和 `src/utils/classRoster.js`，服务端规则见 NPClassworksKV 的 `services/classroomToolsService.js`。

建班联调从没有班级的年级开始，检查重码、并发请求、回包丢失后的手动重试、跨校与学期校验、首次名单保存及旧网页接口。使用 `--serve-class-creation` 可保留独立测试服务供桌面操作。

建年级联调会运行 Windows Console，从零年级学校打开建班窗口，模拟创建回包丢失。核对原请求后选中新年级，建首班并保存一名学生。还会检查年级重码、填写时切换学期、请求归属与旧网页指定学期创建。桌面截图保存在 `.artifacts/grade-creation/desktop-live`。

改名联调从 Windows Console 的建班窗口操作已有班级和学生的年级，覆盖两位管理员的旧版本冲突、回包丢失核对及学期切换，并在 PostgreSQL 核对原年级、班级和学生记录。桌面截图保存在 `.artifacts/grade-rename/desktop-live`。

批量开班联调用 Windows Console 验证 12 班预览、第 7 行冲突与零写入、修正后成功回包丢失、按回执打开名单、重启后从普通班级列表打开同一份名单。HTTP 和数据库检查覆盖管理员竞争、批次归属、旧网页并发占码触发整批回滚、切换学期、跨校请求与旧网页指定学期写入。桌面截图保存在 `.artifacts/class-batch/desktop-live`。

行政班维护联调用 Windows Console 验证代码冲突、并发编辑、停用摘要读取失败、新增大屏后的二次确认、重启后恢复原班及打开原名单。HTTP 和数据库检查覆盖大屏等量替换、学期切换、跨校与只读角色拒绝、旧网页归档学期维护，以及停用前后同一大屏凭据的服务端行为。桌面截图保存在 `.artifacts/class-maintenance/desktop-live`。

学校总览联调用 Windows Console 贯穿旧学期同码、同班两屏、待办定位和返回刷新，并通过真实 NPEP HTTP 配对、首报及新 Host 会话核对回执。另覆盖班级恢复后重新配对提醒、无启用学期、建年级和建班入口、读取失败、切校迟到响应和历史网页查询。桌面截图保存在 `.artifacts/school-overview/desktop-live`。

首台大屏联调在 Windows 上使用与 Console 同级的 NPEduTools 工作副本。夹具在另一所学校的同名班放置 205 台大屏，使新登记的大屏排在旧目录范围之外。测试通过教室端 Host 命令查找、翻页并按原口令接入，重启后在 Console 核对状态上报。服务和客户端使用独立的临时目录。`--serve-first-screen` 可保留服务供桌面验证。

要在 Windows 桌面复验建班，用该服务打印的临时文件运行以下命令。测试从班级栏打开窗口，模拟丢失建班回包，重试确认后保存首份名单，并导出窗口截图。

```powershell
dotnet run --project tests/NPEduConsole.ClassCreationDesktop -c Release -- --live '<测试目录>/desktop.json' '.artifacts/class-creation-ui/desktop-live'
```

要复验 Windows 桌面上的实际保存，把上面的名单命令改为 `--serve-class-roster`，保留临时服务。另开终端运行以下命令，将第一个占位路径替换为服务打印的测试登录文件，最后按回车关闭临时服务。

```powershell
dotnet run --project tests/NPEduConsole.RosterDesktop -c Release -- --live-save '<测试目录>/desktop.json' '.artifacts/class-roster-ui/desktop-live-save'
```
