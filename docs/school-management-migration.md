# 学校管理网页迁移清单

## 学校管理总览与待办

学校管理员选择学校后进入「学校总览」，也可从左栏随时返回。「管理待办」按当前启用学期列出学校配置、具体班级和具体大屏。建年级、单班或批量开班沿用「新建行政班」。对未登记首屏的班级，点击「前往登记」进入原登记区，再由管理员确认登记。对待接入或待上报的大屏，点击「定位大屏」按原班级和绑定 ID 打开对应入口。返回总览时重新读取学校服务。

「大屏状态」分别显示网页首次登录和值守心跳，以及 NPEduTools 配对和有效上报。Console 登记首屏后会出现 NPEduTools 接入待办，登记网页账号也会独立显示首次登录待办。终端成功上报后，同一绑定的首次上报待办消除。KV 保留最近一次有效上报的时间，终端重开 Host 会话仍可查阅该记录。旧数据若已在升级前丢失上报证据，显示「待核对」。原班重新启用后，既有规则判定旧 NPEduTools 授权已失效时，待办提示现场重新配对。

当前学期的班主任、年级职责、本地教师账号、走班和网页大屏值守待办可在 Console 办理。暂无启用学期的待办可打开桌面学期管理，重新启用已有学期或用历史学期建立草稿。网页地址取自 KV 的 `FRONTEND_URL`。地址未配置时，Console 显示原网页办理提示。无需另填监控凭据。

上线先部署 KV 并应用迁移 `20261121040000_npep_device_last_report`，再更新 Console 和网页。旧网页仍可查询指定学期。新接口位于 `/api/v2/admin/schools/:schoolId/management-overview/current`。

## 批量配置随班授课科目

「班级与教务」已选班时，可从目录底部的「全校教务」办学期管理、组织导入、教师账号等学校级事项。返回所选班级时保留原班。

在批量开班结果、班级详情，或暂无随班科目的「任课分配」窗口点「配置授课科目」。批量开班结果会预选本批新班，其他入口预选当前班。可以勾选同年级启用班和本校已有学科，在预览中逐班逐科核对，也可取消任意一个组合。缺少学科时点「新建学科」，保存后会选中服务器确认的新学科，并保留已勾选的班级和学科。继续预览并确认后才写入当前学期的授课规则。

Console 只补设随行政班授课的规则。新增项沿用非必修默认值，已有随班规则及其必修信息原样保留。走班规则、走班来源、任课、名单和访问权限也会保留。所选项目冲突、班级变化或切换学期时，KV 不写入本批。重发相同配置不会新增重复规则。若其他管理员已改过某一项，可在对应行对照预览和当前记录，再重新预览。回包中断时先只读核对实际规则。在同一次登录中关闭窗口后，可从同一学校、学期和入口班级重新打开「配置授课科目」，继续核对原选择。成功后可选择班级与学科进入任课分配，返回总览重新核对缺教师待办。

开设当前学期走班课程时，使用「走班教学班」。指定学期逐科更改使用「教学安排与师资」，整班调整可从同一工作页的「班级全科」进入。本地 Windows 联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --current-subject-setup`，截图默认写入 `.artifacts/current-subject-setup/desktop-live`。

## 学校学科目录

选择学校后，在「班级与教务 → 学科目录」按名称或代码查找，创建或编辑名称、本校唯一代码、类别和显示顺序。目录全校共用，无启用学期也可办理。编辑沿用学科 ID，各学期的授课规则和任课仍引用原学科。

代码重复时可就地修改。另一位管理员先保存时，草稿保留，Console 显示学校当前值，采用当前版本后可重新提交。创建回包中断时，Console 在当前登录会话保留请求编号，可关闭并重开目录继续只读核对。回执只归原学校与账号。返回开科前如遇学期切换，已建学科保留，请选新学期的班级继续。

旧网页可继续维护学科。部署新版 KV 时先应用 `20261121050000_school_subject_creation`，再更新 Console。Windows 与隔离 PostgreSQL 回归可用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --school-subjects`，截图默认在 `.artifacts/school-subjects/desktop`。

## 当前学期行政班任课

在「学校总览 → 管理待办」找到某班某科缺任课教师，点「分配任课」。也可在启用的班级详情点「任课分配」。左侧选择科目、教师和班级，右侧逐班对照当前任课与预计变化。并发修改时会定位到需要重新核对的班级。

新增时选择本校已有教师及主讲或协同身份，可以同时勾选同年级、该科目随行政班授课的其他启用班级。预览列出逐班变化和当前安排。有主讲冲突或预览已过期时，整批不写入。可以取消有冲突的班、选择协同，或单独修改原关系。提交回包中断时，Console 先只读核对服务器当前安排。返回总览后重新读取待办。

新增或调整任课可能授予或提升班级成员权限。修改为协同或移除任课时，已有班级成员权限保留，其他科目和职责授予的访问照常有效。本地教师账号和当前学期走班任课另有桌面入口。上线先更新 KV，再更新 Console，本轮无新增数据库迁移。

本地联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --current-teaching`。使用隔离数据库、Windows Console 和 Edge，截图默认写入 `.artifacts/current-teaching/desktop-live`。

## 当前学期走班教学班

从「班级与教务 → 走班教学班」按年级、学科或缺教师筛选，打开或新建教学班。在「学校总览」点「核对走班来源」会定位到缺覆盖的行政班或需要核对的教学班，点「分配走班任课」会进入对应教学班的任课编辑。

开设或补来源时，选择同年级启用行政班，填写教学班名称、唯一代码和是否允许学生自行选择。预览逐班列出新增、保留和移出，既有同科教学班和随班任课可一起核对。同一行政班可同时作为多个同科教学班的来源。若某班仍有有效随班任课，可打开该班任课处理，返回原走班草稿后重新预览。移出一条来源会保留原授课规则和其他教学班，最后一条覆盖移除后会出现缺覆盖待办。

确认时 KV 在同一事务内复核学期、权限和预览依据，保存目标教学班、来源以及涉及班级的该科规则。保留必修信息、其他科目及既有任课和权限。并发变化时整次零写入。若保存回包丢失，Console 先按本次请求编号只读核对，并按服务器确认的教学班 ID 返回列表。任课另行保存，沿用任课、来源班主任职责和既有成员关系分别生效的权限。当前学期的停用、恢复和改科转到「年级教学安排」。在草稿或归档学期办理同类调整，可从学期管理进入「教学安排与师资」。

上线先部署 KV 并应用 `20261122010000_current_course_group_receipts`，再更新 Console。Windows、学生网页和隔离 PostgreSQL 联调使用 `--current-course-groups`，证据默认在 `.artifacts/current-course-groups/desktop`。

## 当前学期按年级调整教学安排

从「班级与教务 → 年级教学安排」选择年级和科目。也可从「走班教学班」选中目标后点「停用或改科」。逐班对照当前和调整后的授课方式、必修设置、可选走班和任课。可多选行政班，逐班调整，在同一份方案中加入走班停用、并入、恢复、改科和任课，然后统一预览并保存。从总览可继续办理留待分配的任课。

停用和恢复沿用原教学班 ID，并单独显示任课、成员权限、邀请和发布影响。没有任何发布目标或任课历史时，核对来源与权限后可原 ID 改科。已有发布（含历史版本）或任课记录时，按新科目另开班使用新代码与新 ID，可在同一方案明确停用原班。原记录保留在原编号，任课与独立访问不会自动转给新班。现有桌面任课和网页入口移除或更换走班教师时也会保留失效记录，仍能核对改科限制。升级前已物理删除且没有其他证据的历史无法重建。学生选课保存在浏览器，本页展示各班的可选项变化。失效选择由学生重新确认。

KV 在同一事务核对权限、当前学期与逐项确认的来源、规则、任课、发布和权限影响。发生相关并发变更时整份零写入，Console 定位变化并留住草稿。回执中断后按学校、操作者和本次请求只读核对。

上线先部署 KV 并应用 `20261122050000_grade_teaching_plan_receipts`，再更新 Console。隔离 PostgreSQL 回归使用 `--grade-teaching-plan-db`，Windows Console 与 Edge 学生和教师链路使用 `--grade-teaching-plan`。证据默认保存在 `.artifacts/grade-teaching-plan`。

## 学校自习管理

在「班级与教务 → 学校自习」按年级和日期查看当日实际安排，默认打开本周。并列列出日常和考试时段、来源和班级。窄窗从当天列表进入班级详情，返回时保留日期、班级与焦点。跨午夜的场次保留原开始日，结束前仍会出现在次日。日常由教室 ClassIsland 的学校时间判断，考试用 Windows 的北京时间。

「编辑年级安排」和「编辑本班安排」可以分别维护日常或考试的每周时段、生效和截止日、指定日期停排与调休。班级可独立设置、关闭或恢复继承。仅当班级和年级均未提供自习策略时，才可能沿用旧版定时噪音安排。预览完整列出受影响的班级，也列出因独立或关闭而保持原状的班。保存只改明确编辑的时段或启用规则。旧网页修改了相关依据时，本次零写入，保留草稿并定位变化后重新预览。排期丢回包可以按同一请求只读核对。

从本班详情打开「座位图与逐屏状态」可预览、发布、替换、撤回，也可从仍有图片的历史版本重新发布。图片归自习所在班级，即使作业来自其他班。逐台大屏按绑定编号列出配置版本、Host 下载、展示端应用与最近打开的时间。前屏打开旧图时，下载的新图在关闭再打开后可见。旧图或过期证据不会计为已应用新图。同班后屏缺回执时单独显示待核对。座位图使用独立的发布回执。「本日场次与回执」从所选日期和班级打开报告及教室回执。

本班详情的「监测策略」可以核对生效来源，编辑本班独立策略或进入年级监测。噪音阈值可用 dBFS 或现场校准的估算 dB(A)。高线持续时间同时用于超限提醒和拍照判定。年级保存前逐班核对继承、独立和关闭，原排期、作业来源和展示设置随策略保留。把继承班改为独立设置会停止整套策略的年级继承。定时自习与符合条件的手动自习可触发拍照，摄像头继续在教室现场选择。

本班详情的「展示与当天作业」按学校日期预览学生页。可选噪音状态样式、当天作业开关、每班本班或指定的来源行政班，以及 15–600 秒的轮播间隔。指定班级按当期授课规则展开相关走班，同一发布只出现一次，并保留各命中来源。作业借用不改变座位图、照片或访问权限。Console 的内容预览按文字分段，大屏按现场布局排页。继承班默认可改年级展示，也可明确以现行年级策略为基础设为本班独立，整套策略随之停止继承。首次预览和提交均核对该班继承的年级及策略版本，原依据过期时保留已改字段并要求重新核对。班级未安排、已关闭或仅有旧排期时从原安排入口办理。学校保存回执、Host 应用版本和近期窗口可见观测逐屏列出。窗口可见只证明观测时自习窗口在显示。展示保存沿用既有回执库和教室协议，无新增迁移；先部署 KV，再更新 Console。隔离联调用 `--study-display`，真库专项用 `--study-display-db`。

本班「照片与退出记录」按日期及原班级查询。进入「本日场次与回执」后也可从每台设备的已上传报告打开同一记录页，按学校、学期、班级、设备和场次片段核对。学校配置、教室应用、采集信号及已存照片均有独立证据，退出记录可以没有图片。只有本校具有有效 OWNER 或 ADMIN 会话的账号可以列出、预览、下载或删除；下载由管理员选定位置，查看、下载和删除沿用服务端审计。在线保留期缩短会提前照片和退出记录的到期时间，延长保留期沿用既有记录原来的到期时间。备份副本的保留按部署处理。旧网页保留原有监测、报告及照片入口。

先部署 KV，再更新 Console，无新增数据库迁移。旧网页和当前教室端协议继续兼容。Windows Console、实际旧网页、隔离 PostgreSQL 与 NPEduTools Host/WPF 联调用 `--school-study`，专项数据库用 `--school-study-db`。证据目录默认是 `.artifacts/school-study`。

## 开学组织导入

从「班级与教务 → 开学组织导入」选择本校已启用学期或草稿及一个年级。从「学期管理」选中草稿后点「导入草稿组织」固定使用该学期。读表、核对差异和查看结果均在主窗口。可打开旧组织 JSON、载入七班制示例、在页内按列粘贴 Excel，也可直接编辑行政班、学科规则、教学班和来源。页头始终显示所选学校、学期和年级。载入 JSON 保留已选年级，年级尚为空时可采用文件声明。文件声明不符时并列显示两个目标并保留原表；载入匹配文件若会替换未保存表，需明确确认，也可取消。旧文件中的认证、学校设置与启用指令不进入桌面写入。

「预览导入差异」逐项列出现状与导入后结果，窄窗可选中行展开两栏值。按 F8 定位阻断项，选中差异后可按 Enter 回到原单元格。返回差异页会恢复筛选及选中行，实际改表后需重新预览。新增学科全校可见；已有学科继续使用原 ID、名称、类别及顺序。默认补充，保留未列出的班、授课规则及来源。只有对指定班级或教学班选择「按表替换」才会移除预览列出的关系。同码停用班、跨年级重码、与现有任课冲突和有历史的走班改科在预览中阻断。确认时复核当前状态，并发改动使整批零写入。回包中断时仅按本人原学期和原请求查询服务端回执。同校另一学期可以继续编辑；明确打开相应的待核对请求后才读取原结果。

当前学期或草稿导入完成后，都可点「继续分配教师」，沿用回执中的学校、学期和年级。也可从回执进入任课或草稿的「启用前检查」。从这些入口回来仍可核对原回执。导入仅写教学组织，草稿保持准备中。首次建校由登录页办理，归档学期从选中的学期进入「批量更正」。

主窗改造无新增数据库迁移。已有导入能力的环境可直接更新 Console；初次部署导入功能时，先应用 KV 的既有迁移 `20261122060000_school_organization_import_receipts` 并更新 KV。隔离 PostgreSQL 回归用 `--organization-import-db`，Windows Console、实际 Edge 旧网页、学生和教室联调用 `--organization-import`。两种模式都由 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录>` 运行，证据默认在 `.artifacts/school-organization-import`。

## 本校教师账号

在「班级与教务 → 教师账号」可按姓名或短账号搜索、新建、停用和恢复普通本地教师。学校尚未启用学期或没有班级时仍可办理。个人 PIN 模式可重置 PIN，学校通用口令模式只建短账号。普通教师批量建号、OAuth 邮箱邀请和班级访问分配见下节。所有者也可从具体教师打开「账号与权限」，按原账号授权。

也可在任课、班主任、年级组长的教师选择区点「新建教师」，按已确认的账号 ID 回选并保留上一页草稿。新建仅授予普通学校成员身份，任课和职责等待管理员单独确认保存。同名教师按短账号区分，本校重码时可核对原账号或改用其他短账号。提交回包中断时按本次请求编号只读核对。

「学校总览」可按账号定位已停用仍有任课或有任课但未首次登录的教师。详情分开显示账号状态、真实登录时间、当前学期任课和职责。停用或重置 PIN 会退出旧会话，恢复沿用原账号；任课、岗位和班级成员关系保留。首次登录提醒只在教师实际登录后消除。

上线先部署 KV 并运行迁移 `20261121060000_school_teacher_account_receipts`，再更新 Console。Windows 与隔离 PostgreSQL 回归使用 `--teacher-accounts`，证据在 `.artifacts/teacher-accounts/desktop`。

## 开学教师名册与班级访问分配

从「开学组织导入」结果点「继续分配教师」，在主窗沿用回执确认的学校、学期与年级。也可从「班级与教务 → 教师账号 → 批量导入与分配」进入同一套工作页，自行选择范围。录入页可粘贴 Excel、打开旧教师分配 JSON 或搜索已有教师。旧文件声明的学校、学期或年级不符时显示两个目标，保留原教师表。只建本地账号时可不选学期；个人 PIN 只用于新账号，重导保留已有凭据、状态和会话。通用口令模式只需短账号。邮箱模式可分配给已验证账号，或预分配给待登录邮箱。预览与查询用短账号或邮箱区分同名教师。

可为行政班与走班教学班设置教师、助教、只读，也可明确移除直接访问或撤回待认领邀请。预览按教师和教学空间显示原角色、计划角色及影响。任课和岗位职责各自生效，移除一条直接成员关系后仍可查看由职责或任课产生的访问。表外关系保持原状。降级、移除和撤回都要确认对应对象。管理授权与所有者交接从「账号与权限」办理，归档普通教师访问从「学期管理 → 批量更正」办理。

核对页集中显示差异，窄窗在所选行内展开前后权限，F8 和 Enter 可回到具体输入项。保存时 KV 在同一事务内复核学校权限、学期和预览涉及的身份及关系。并发变动时整批零写入并标出相应行。回包丢失后按本校、本人、原请求只读查回；由组织回执进入时只显示该学期及年级的请求。本次录入的初始 PIN 不会出现在回执或待核对记录中。结果页可按教师或班级核对访问及邀请，也可从当前学期的回执继续办理所选教师、所选班的任课。返回主窗分配时恢复原结果行，再返回组织时恢复原组织回执。

本次主窗改造无新增数据库迁移。已有教师分配能力的环境可直接更新 Console；初次部署该能力时，先应用 KV 既有迁移 `20261122070000_school_teacher_allocation_receipts`。隔离 PostgreSQL 用 `--teacher-allocation-db`，Windows Console、Edge 旧网页与教师登录联调用 `--teacher-allocation`。桌面复验在控制台提示后，用原生文件对话框依次打开三份路径已打印的测试 JSON。证据默认在 `.artifacts/teacher-allocation`。

## 学校管理账号与权限交接

选中学校后从左栏「账号与权限」进入，无需启用学期。所有者及管理员可核对本校账号名册。导出的无密 CSV 包含全校账号、身份、角色、登录状态、最近登录和当前学期的直接教学空间，不受页面筛选影响。只有所有者可以新建管理账号、变更管理权，或为其他管理账号重置 PIN、停用、恢复和注销本校访问。短账号已存在时按账号身份核对后另行授权。本人改 PIN 需验证原 PIN。

新授权须用适用于该身份的方式重新登录。既有教师通用口令会话不会取得新增管理权，独立任课、岗位和直接成员关系仍按原规则生效。管理权包含查看全校自习照片的权限，收回后立即按现有会话重新验权。角色变更、停用登录和注销本校权限各自有影响预览。学校仅有一名所有者时可以继续工作。最后一名可用所有者退出前，要先确认另一位已启用的所有者在获权后成功登录。Console 与网页登录都可取得 OAuth 登录证明，和本地 PIN 证明分别显示。跨校成员角色按各校现行授权核对。

保存回包中断时先按原请求只读核对。暂未找到回执时可明确选择按原编号重试，服务器会重新核对预览。需要 PIN 时须重新输入，只有服务器明确确认重试实际写入才可交付该次输入的 PIN。部署前先应用 KV 迁移 `20261122100000_school_management_authority`，再更新 KV、NPClassworks 网页与 Console。首次建校和服务器恢复密钥仍可在网页办理。隔离 PostgreSQL 回归用 `--management-accounts-db`，实际 Windows Console 和 Edge 联调用 `--management-accounts`，证据默认在 `.artifacts/management-accounts`。

## 学校管理员 OAuth 桌面登录

在登录页填写 KV 地址后，点击「使用浏览器登录」。服务器配置多个提供方时先选择。浏览器确认页显示服务器、提供方及本窗口的核对码，点击继续后完成 OAuth 认证，再返回 Console。短账号和 PIN 登录继续可用。登录后仅列出此会话当前具有 OWNER 或 ADMIN 权限的学校，单校直达总览，多校按校名和角色选择。

原窗口接收并确认本次领取后，KV 激活该会话并记录登录证据。浏览器完成但尚未领取、取消或领取回包中断都不形成有效接任登录。确认已提交但响应中断时，Console 凭原会话只读核对学校。授权变化按学校分别核对，较早的认证结果无法继承随后授予的新权限。

先更新 KV，再更新 Console。使用上轮 `school_management_authority` 表，本轮无需新增数据库迁移。身份提供方继续使用 KV 原有固定回调。多实例代理沿用现有 OAuth 会话同实例处理安排。隔离验收用 `--desktop-oauth`，证据默认在 `.artifacts/desktop-oauth/acceptance`。

## 学校基本资料与教师登录设置

选校后从「账号与权限 → 教师登录设置」进入，也可从「教师账号」或「批量导入与分配」打开。有效的本校所有者和管理员均可办理，学校代码只读，无需启用学期。单改校名可直接保存。切换个人 PIN、学校通用口令、OAuth 邮箱方式，改变备用 OAuth 或轮换通用口令时，先核对影响。普通启用账号与未认领的邀请分别计数，按账号或邀请的实际编号跳到补办入口。返回后重新读取校内登录条件；批量分配保留教师表并重新核对当前登录规则。

切换个人 PIN 与通用口令影响教师下次登录。已有会话不会因本操作整体退出，任课、职责及成员关系维持原状。进入仅 OAuth 或关闭备用 OAuth 后，现有会话的本校直接教学访问、作业和通知仍由服务端按当前方式验权；邀请在本校允许 OAuth 且身份验证后才可认领。独立职责和其他学校权限继续按原规则。管理员个人 PIN 和适用的浏览器登录权限不随教师策略改变。补设或重置某位教师 PIN 沿用个人账号的会话失效规则。

保存时 KV 核对操作者权限、学校当前版本、账号及邀请等影响依据。并发修改保留非敏感草稿，须重新核对。回包中断先按本校、本人和原编号查回。轮换口令只在确认保存时提交，预览与回执不包含口令。旧网页共用保存契约。已建学校用旧组织导入时，文件省略的教师策略保留服务器原值，显式不同的声明会提示先到登录设置办理并阻止组织写入。首次设置向导保留原来的初始化方式。

先应用 KV 迁移 `20261122110000_school_profile_receipts` 并更新 KV，再更新网页和 Console。部署后请管理员刷新已打开的旧网页再修改学校资料。隔离 PostgreSQL 用 `--school-login-profile-db`，空库首次设置用 `--school-login-profile-setup`，Windows Console 和 Edge 联调用 `--school-login-profile`。证据默认在 `.artifacts/school-login-profile`。

## 首次建校与整校迁入

从登录页顶部打开「首次配置学校服务器」。同源部署填写师生网页地址，前端页面和 KV 可由网关按路径分流。分域时勾选「使用独立 KV 地址」并填写实际 API 根；只有 KV 地址时可明确选择先办理 KV，网页连接留待核对。同源 Compose 应显式配置本站的 `VITE_DEFAULT_KV_SERVER`。分域部署中的网页构建地址、KV 的公开地址及允许网页来源由部署人员配置。

Console 分别核对 KV 的真实状态和网页 `/.well-known/npclassworks-deployment.json` 中声明的 API 地址。声明不一致会阻止提交部署密钥；旧网页缺少声明时，需另行核对对应地址再继续。「在浏览器检查网页连接」打开该网页的 `/connection-check.html`，只带预期 API 根，浏览器再用其实际构建配置检查 API 与实时连接。KV 状态、部署声明与浏览器结果分别呈现。接口未找到或响应不可识别时不开放桌面写入，原网页版 `/setup` 仍可按支持情况办理。

空白服务器可「新建学校」或「从迁移包恢复」，已有学校数据但未完成时可「继续初始化」，已完成时返回常规登录。首次建校在同一主窗填写学校、首位所有者、首学期及教师登录方式。数据写入后用所有者本人身份真实登录，完成初始化后总览提供该学校、该启用学期的「创建首班」，接到既有年级、建班和名单办理；迁入沿用已有班级。授权过期时在同一目标重新输入密钥。响应中断先读取原目标结果。返回连接检查或更换目标会清除凭据并重新核对。

源服在侧栏「学校迁移」按所选学校核对数据。本校 ADMIN 可以查看准备情况，OWNER 用本人 PIN 或可验证的新鲜 OAuth 认证导出。正式换服前请先安排源服停止业务写入，再导出最终包。目标预检核对地址、学校、包版本、可用所有者登录方式及逐屏接入。成功回包丢失时按原迁移编号只读找回结果。实际登录后才显示初始化完成。网页仍可办理首次设置和迁移。

v2 另外迁移学校自习设置、座位图版本及保留的图像、可沿用的班级口令校验资料及授权版本。自习照片与退出记录留在源服并按原期限处理。原网页登录会话、原生凭据、接任登录证明、待执行命令均不带入。原生终端须逐屏重新配对，后续上报在既有设备页核对。v1 包明确提示缺失范围，需要这些配置时在新版源服重导。

首次配置入口和连接检查不新增数据库迁移。若既有环境尚未部署整校迁移功能，源、目标 KV 仍须应用 `20261122120000_school_transfer_boundary`。升级时先核对 KV 版本及网页/API 公开地址，再部署包含声明和检查页的网页构建与 Console。服务器的部署密钥与身份提供方单独管理。Windows 首次建校回归用 `--first-school-console`，包含同源/分域 loopback 网关、故障注入、续办和建班。真实双服务器迁移用 `--school-transfer`，数据库回归用 `--school-transfer-db`。证据目录默认 `.artifacts/school-transfer`。

网页首次配置可在提供 Windows x64 发行包时引导管理员先从 Console 办理。下载清单和 ZIP 在前端部署的 `/downloads/npeduconsole/` 同目录。完整解压后打开 `NPEduConsole.App.exe`，在「首次配置学校服务器」检查实际目标。没有发行配置、旧服务或需要继续使用浏览器时，仍可进入原 `/setup`。发行目录只包含公开程序及核验信息；安装密钥通过现有部署渠道单独交付。此分发步骤无需新增数据库迁移。

## 开学配置

从「学校总览 → 开学配置」继续准备班级与课程、教师与岗位、教室接入。本校管理员可随时重开读取启用学期的进度，包括新建、迁入和日常登录后的学校。宽窗并列事项与证据，窄窗进入单项后可返回原事项和焦点。按实际学期、班级、教学班、学科、教师和大屏绑定进入既有办理页，返回后重读 KV。学期切换或原对象变化时，先核对更新后的清单。

教师账号、直接访问、待认领邮箱邀请、学科任课和岗位分别核对。组织导入后可继续分配教师访问，再按原回执进入任课。含任课和岗位的旧完整师资文件在「教师与岗位 → 导入完整师资方案」办理。逐屏核对网页账号、历史首次网页登录、当前凭据心跳、原生当前配对及有效上报，证据不足时显示待核对。

师生及网页大屏使用网页地址，教室端 NPEduTools 配对使用 KV 地址。清单显示首次配置选定的网页或 KV 提供的网页站点，网页地址未知时需另行核对。可打开浏览器检查实际连接。

新本地教师的个人 PIN 和本次设置的网页大屏 PIN 可在原办理页逐个复制或另存一次。单独建号或重置教师 PIN 时先勾选「保存后复制或另存本次 PIN」。KV 须确认本次提交确实写入，导出前还要核对账号和凭据版本。仅找回历史回执时显示办理结果，需要发放新 PIN 时由管理员明确重置。清单和历史回执只保留无密数据。学校通用口令及邮箱登录模式提供相应登录说明。

上线先更新 KV，再更新 Console。开学配置沿用既有管理员权限，本轮无需数据库迁移。Windows 宽窄窗、隔离 KV/PostgreSQL、实际 Edge 教师及网页大屏与 NPEduTools 前屏接入联调用 `--school-opening`，证据默认在 `.artifacts/school-opening`。首次建校和整校迁入专项也检查进入此清单。

### 导入完整师资方案

有效本校 OWNER 或 ADMIN 从「学校总览 → 开学配置 → 教师与岗位」打开专页。本校个人 PIN 或通用口令模式可为当前启用学期办理。选择旧网页 `/setup` 使用的完整师资 JSON 后，核对文件声明的学校代码、学年和期序与页头。普通教师批量分配识别到匹配的完整文件时，会在保留原表的同时询问是否进入专页。邮箱模式继续使用教师分配与邮箱邀请，旧网页首次初始化入口仍可使用。

按短账号区分同名教师，按真实学期和对象逐人预览账号、直接访问、任课及岗位。需处理现任人员时，从问题打开原任课或原岗位，返回后按原文件和教师重新预览。已启用的既有普通教师沿用原凭据和会话；已有身份状态或安排冲突时先核对。确认后，服务器在同一学校锁事务中复核并保存整份方案，旧预览不部分写入。窄窗按教师查看关系，底栏保持整份方案的变更、阻断和确认。

回执列出本次已确认的逐项前后值。断线先只读找回，退出后本人可在同一服务器和学校重开核对。Console 在本地只记原编号、作用域和不含 PIN 的确认依据。未查到回执时，可重新选择原文件并在依据仍一致时显式按原编号重试，也可明确结束旧申请再重新预览。只有本次确实应用的新 PIN 可按账号复制或另存一次，回执没有 PIN。

部署先应用 KV 迁移 `20261123020000_staff_configuration_receipts`，再更新 KV、Console。实际 Windows 及隔离 KV/PostgreSQL、Edge 教师登录验收用 `--staff-configuration`，证据默认在 `.artifacts/staff-configuration`。

## 当前学期教师职责

在「学校总览」点「办理班主任」或「办理年级组长」，按学校、学期及对象 ID 打开对应编辑区。指向教师的提醒会定位到该账号。也可以从「班级与教务」的班级详情打开「班主任」，或从年级标题旁打开「年级组长」。

按姓名或账号搜索本校教师，对照当前和保存后的安排。交接时逐行决定原负责人转为协同班主任或副组长，还是卸任。原来存在多位主要负责人时，全部列出，预览前需把各人去向确定，并保留至多一位主要负责人。预览中的岗位联动提醒沿用现行学校设置。

保存时 KV 核对当前学期、学校管理权限、对象状态、教师归属和版本。并发修改时零写入，Console 显示服务器当前安排并保留草稿；采用当前版本后重新预览。回包中断时先只读核对，在同一次登录中可重开同一对象继续核对。返回总览会重读待办并恢复筛选与位置。

职责、任课及班级成员权限独立生效。班主任和协同班主任可管理本班、查看相关走班，年级组长和副组长可管理本年级教学空间。卸任保留原任课和成员关系。全校岗位联动规则可从「师资核对」办理。当前学期岗位快捷入口的 Windows 与隔离 PostgreSQL 验收使用 `--current-staff`，截图在 `.artifacts/current-staff/desktop`。

## 为未匹配大屏安排新班

在「学期启用结果」选中仍绑定原班的大屏，或在「学校总览」打开该屏的待安排事项。表单按绑定编号读取原学期和原班，按年级、班名或代码搜索当前启用学期的行政班。选中班级后先核对该班已有大屏，再确认安排。任何现有学校管理员都能接手，原启用回执和个人安排回执仍分别归各自操作者。

保存沿用原大屏编号、网页账号及 PIN，旧网页会话失效，重新登录后可继续使用该账号。迁入屏按现有流程现场重新配对；目标班原有大屏保留绑定和凭据。结果区分待配对、待首次有效上报和已上报。原启用结果仍记载当时没有匹配，另显示后来安排和当前设备状态。

目标班、已有大屏、当前学期或原绑定已变化时，KV 拒绝旧确认。回包中断可按原请求只读核对，服务器未查到前保持原编号。已通过旧网页改绑且能核对当前归属时，Console 显示服务器观察到的目标。旧网页的大屏管理入口保留。

上线先应用 KV 迁移 `20261122040000_term_screen_placement`，再更新 Console。本地验收使用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --term-screen-placement`；数据库回归使用 `--term-activation-db`。

## 学校审计记录的退役条件

使用本地管理账号或桌面 OAuth 登录 NPEduConsole，选择学校后从左栏打开「审计记录」。即使学校尚无启用学期、班级或大屏，也可以查阅。两端读取同一份学校 `AuditLog`，KV 对每次查询核对本校 OWNER 或 ADMIN 权限。

| 管理员要做的事 | Console 中的对应操作 |
| --- | --- |
| 找出某天失败的操作 | 选择操作来源、类型、结果及本地起止日期，读取选中日期全天的记录。 |
| 查更早的记录 | 按时间倒序浏览，点击「加载更多」查看下一页。点击「刷新」或「应用筛选」都会从第一页开始。 |
| 核对一条记录 | 查看记录编号、操作者或大屏、时间、操作对象、请求路径、HTTP 状态、来源 IP 和脱敏参数。旧记录缺少的字段按缺失显示。 |

**审计一级菜单试点。** 默认展示原菜单。试点开启后，宽屏侧栏及窄屏「管理页面」将审计放在「网页版兼容」下。旧书签 `/classworks-admin?section=audit&school=<学校ID>` 可直接查询；「继续使用网页版」聚焦原查询。学校无启用学期也可办理。网页只在本站提供可核验的 Windows 发行件时提供下载。

**现场启用与回退**

1. 先在试点站点核对当前网页版本和学校实际使用的 Console 发行版。用学校平时的个人 PIN 登录，在网页旧书签和 Console 所选学校查同一条记录，记录两端的编号、时间及成功或失败。使用 OAuth 的站点另验其实际提供方。
2. 只对接受试点的网页部署启用。编辑站点的 `/.well-known/npclassworks-deployment.json`，在原有 `schemaVersion: 1` 声明中增加布尔字段 `"adminAuditNavigationPilot": true`，保留 `apiBaseUrl` 等现有字段。也可在构建该站点前设置 `VITE_ADMIN_AUDIT_NAVIGATION_PILOT=true`。同一站点服务的所有学校共用这份导航配置。
3. 刷新管理页，在宽窗和窄窗从「网页版兼容 → 审计记录」打开查询，再打开旧书签。核对原学校和记录，确认可以继续在网页查看。未获现场确认时保持原菜单。
4. 回退时把同一份已部署声明中的该字段改为 `false` 或删去，重新打开或刷新管理页，确认一级菜单恢复且同一书签仍能查询。若网关缓存静态资源，先确认浏览器收到更新的声明；若发布流程自动重建文件，同时取消构建开关。无需还原学校数据或修改 KV。

### 常规学校管理入口试点

首页「学校管理员」、教师账号菜单、设置「进入管理后台」及已开通实例的 `/setup` 管理按钮共用入口。默认进入原管理网页。试点站点先显示选校与 Windows 管理端下载，管理员可以继续在所选学校使用网页版。同源部署在 Console 填页面显示的共用地址，分域部署填「Console 登录用 KV 服务地址」。选校后的学校代码用于个人 PIN 登录。

在校方核对本站部署的 KV、网页与 Windows 发行包后，可在本站 schemaVersion 为 1 的 `/.well-known/npclassworks-deployment.json` 增加布尔字段 `"adminManagementHandoffPilot": true`，保留 `apiBaseUrl`。重新构建时可设 `VITE_ADMIN_MANAGEMENT_HANDOFF_PILOT=true`。此配置作用于该部署的所有学校。已开通实例、声明地址匹配且本站有可校验的 Windows x64 包时，引导才提供下载。回退时删掉该字段或设为 `false` 后刷新；重建时也移除相应构建参数。审计菜单的开关独立。

校方用实际管理员账号从日常入口选校、获取该站发行包，并登录原校总览。再用「继续使用网页版」与原书签核对学校、学期和对象；有网页大屏的学校还应核对锁定与临时退出到期。可在隔离环境用 `--management-handoff` 复跑同源和分域的 Edge 下载、Windows 登录及网页版返回，在 `NP_CONSOLE_ENTRY_RELEASE_DIR` 指定发行包与清单所在目录。

「学校总览」和「开学配置」中，全班大屏均已停用时按启用学期、行政班编号列出停用绑定。选择一台后可核对影响并确认恢复。旧 KV 缺少桌面值守接口时，从已授权的旧目录核对同班停用绑定，选中后按该屏编号和原班打开网页版。已有逐屏待办与旧书签沿用其目标参数。

**忘记本地所有者 PIN** 时，在 Windows Console 0.1.5 登录页点「忘记所有者 PIN」。核对 KV 服务地址，从公开目录确认学校名称和代码，再填所有者短账号、该服务的部署恢复密钥和两遍新 PIN。换服务器或部署路径后须重新选校并填写账号。没有启用学期的学校也可办理。成功后该账号重新启用、解除登录锁定，所有设备上该账号的现有登录均须重新认证。原学校角色、任课和岗位保留。回到登录页后，由本人输入新 PIN。

若显示「恢复结果暂未确认」，在原服务器、原学校、原短账号用刚填写的新 PIN 登录核对。此接口没有本人请求回执，能够登录只说明该 PIN 当前有效。客户端不会自动重复恢复。个人在已登录状态下可用原 PIN 改自己的 PIN，另一位在任所有者可从「账号与权限」办理目标账号的重置。旧网页的服务器密钥恢复入口仍可使用。隔离环境可设置 `NP_CONSOLE_ENTRY_RELEASE_DIR` 指向 Windows 包与清单，运行 `--owner-recovery` 验证同源与分域两条路径。

正式关闭 `/classworks-admin` 前，学校仍需现场验收所有者 PIN 恢复和教师凭据交付，核对网页管理 OAuth 固定回跳及旧书签。部分栏目在原校不可访问时会选择其他可管理学校或启用学期，仍须核对无权时的实际落点。首次建校、师生与网页大屏继续使用各自入口。

### 首批网页整页停办试点

校方用 0.1.6 和本站实际 KV 验收后，可在前端 `/.well-known/npclassworks-deployment.json` 的 `schemaVersion: 1` 声明加入 `"adminRetiredSections": ["audit", "students"]`。默认空名单，按站点启用；保持 `apiBaseUrl` 与网页实际连接一致。审计及学生名单的旧书签保留原 URL，启用后显示原校、原学期和办理路径，并可从本站获取可校验 Windows 发行件。没有学期的学校可办审计。显式指定的学校失权或学期不存在时显示原编号。网页等待声明期间不启动两项旧业务。

单项回退删对应值，全部回退清空或移除字段。打开原页的管理员先保存或取消草稿，再重新打开。旧审计导航、常规入口开关及旧 KV 的其他回跳保留原用途。声明确认失败时可以重新核对或明确选兼容网页。此次与 0.1.6 已有能力配套，无需重打桌面包或迁移数据库。

**关联入口。** 「学期管理 → 选中学期 → 查看诊断」核对所选学期与全校启用学期。教学、组织和师资事项按已知对象编号打开，返回保持筛选和焦点并重读。设备栏只列读取时的实际绑定和带时刻的证据。历史值守缺乏归属证据时保持待核对。首页继续显示当前学期。

从学校总览的缺任课待办、班级详情或指定学期诊断进入当前任课时，教师选择、逐班预览和保存都在主窗。待办锁定班级和科目，班级详情固定班级并可选择科目。宽窗在右侧选教师，窄窗展开选择页，均显示同名教师的账号。可暂存本次登录中的原班原科草稿，换入口重开后重新预览；切校后只显示所选学校的草稿，回到原校仍需核对学期、原班和原科。成功回包中断时按原班科核对服务器安排。返回班级详情恢复原按钮，返回总览或诊断重读相应待办。归档任课仍先打开只读的教学安排，显式选择更正后再编辑。

归档「批量更正 → 核对本年级教师访问」可对指定待认领邀请单独确认撤回。系统复核原学期、空间、邀请版本和认领状态。教师账号和任课／职责表单的邮箱分配走桌面工作台，开科草稿可打开桌面学科目录后回来。「账号与权限」可导出无 PIN 的全校名册。

**交付本批教师的初始 PIN**　Console 0.1.6 的「批量导入与分配」与「导入完整师资方案」均可在成功结果页一次另存多位新教师的凭据。在名单中按短账号核对同名教师及交付状态。已有账号沿用原凭据，已单人交付的账号从待发名单移除。选好文件位置后系统重新读取校权、办理范围与每个账号的凭据版本。一人已变化时整份文件保持原样，返回结果重新核对其余教师。取消或写盘失败可以在本页重试。

CSV 含明文 PIN，由负责发放的人保管；在 Excel 中导入时将短账号、PIN 列设为文本，可保留前导零。普通批配成功后目录暂时读取失败，可留在同一结果页，在 10 分钟内重读目录恢复交付。离开结果、撤权或只读找回回执后，管理员仍可查办理结果，需要新 PIN 时从教师账号页明确重设。通用口令和邮箱模式按各自方式登录。兼容网页的教师分配导出仍留在原流程，已有短账号再次导入会按旧规则更新凭据。

隔离验收可将 `NP_CONSOLE_ENTRY_RELEASE_DIR` 指向发行 ZIP 与清单所在目录，运行 `--teacher-batch-release`。同源和分域两种部署分别从 Edge 下载、核对发行包，从 Windows 文件选择器保存本批 CSV，再用文件中的 PIN 登录对应教师账号。

浏览器的「设置 → 故障诊断」下载本浏览器的本地诊断包，学校总览保留带该页大屏证据的诊断入口。早期指定学期诊断及归档撤邀要求配套 KV。对已运行配套版本的站点，本轮导航只需更新 NPClassworks 网页，无新增数据库迁移。

在 Console 仓库执行 `node tests/live-kv.mjs ../NPClassworksKV "<PostgreSQL bin 目录>" --entry-retirement-pilot` 可复验。本地测试在隔离网页修改部署声明，实际从管理页登录并比较两端的记录编号、时间和结果，覆盖多校历史返回、无权书签及同班双屏。设置 `NP_CONSOLE_ENTRY_RELEASE_DIR` 指向含 `console-release.json` 与 ZIP 的本地发行目录，还会通过 Edge 下载该版本并核对字节数和 SHA-256。输出位置由 `NP_CONSOLE_ENTRY_EVIDENCE` 指定。

## 全部学期管理与异常切换

从「班级与教务 → 学期管理」按学年查看全部、启用中、草稿和已归档的学期。全校实际启用的学期固定展示，查看另一学期时仍显示原值。从学校总览「暂无启用学期」也可进入。仅剩归档学期时可直接「重新启用」或「以此建立新学期」。没有任何学期时才引导初始化。

从所选学期建立草稿时填写学年、学期序号、名称和日期。预览与实际复制使用同一继承计划，默认复制教学空间成员权限、有效任课及有效职责，未认领的 OAuth 邀请默认不选。预览可逐个核对走班来源、任课和年级或班级职责。取消任课仍可能通过单独继承的成员权限保留教师访问。学生名单需另行准备。

来源配置或当前学期发生变化时，服务端重新核对，原表单保留。若本次成功回包中断，Console 先按原学校、操作者及请求编号查询回执。只有服务端认领的草稿 ID 用于打开本次建立结果。同学年同学期已存在时，也可独立打开已有草稿。

启用前检查区分阻断、一般提醒与大屏影响。按绑定编号逐台核对原班、默认同码匹配的新班及无匹配状态。可确认的既有 NPEduTools 配对在默认改绑后需现场重新配对。创建和查看草稿不会改动正在使用的学期、大屏绑定或原生配对。

选中学期后可预览启用，或从「更多操作」单独归档、转回草稿。预览说明学生提交后的入口，以及该校是否仍具备整校迁出所需的启用学期。启用时可选择按行政班代码迁屏或保留原班。只可明确接受预览列出的缺年级、缺班、走班缺覆盖或来源、停用账号遗留任课或职责等例外。必修走班缺可选组会阻止相关学生提交完整选课，选修可选不修读。规则或访问矛盾、权限失效、依据不足或预览过期仍会阻止提交。KV 在同一事务核对并保存，依据变化时零写入并指出变化。回包中断按原学校、账号和请求编号查回，可在该学期详情重开本人历史回执。

结果页区分当时的学期、改绑和安排回执与大屏现在的归属及上报。离开启用状态会撤销原生旧配对，保留原班或重新启用同一学期均不会恢复旧凭据。需要接入的大屏须在现场配对，逐台收到有效首报后才消除相应待办。选择按代码迁屏时，没有匹配班的屏保留原班，可从本轮回执或总览安排。人工安排按启用轮次和绑定 ID 核对，历史安排不会消除本轮的新待办。历史资料只在有明确关联时归入相应轮次，模糊的旧安排仍可按原编号核对。网页大屏值守状态仍由其自身的回执判断。

部署先应用 KV 迁移 `20261122123000_term_activation_rounds` 及之前的迁移，再更新 KV、NPClassworks 和 Console。更新后的桌面和网页使用同一写入规则。缓存中的旧网页如果没有核对过本次影响，归档、转草稿和强制启用会提示刷新后重办。联合验收使用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --term-status`，独立数据库回归使用 `--term-status-db`。证据默认在 `.artifacts/term-status/final`。

## 指定学期的年级、行政班与学生名单

从「班级与教务 → 学期管理」选择学期，点「班级与名单」。草稿的启用前检查可点「准备班级与名单」。目录、班级资料和名单在同一主窗，页头显示所选学期及状态、年级与班级代码，主窗顶部继续显示全校启用学期。选择年级可修改名称、代码和显示顺序，也可新建年级、单独建班或批量开班。返回目录保留所选原班和操作焦点。停用或恢复沿用班级影响确认，原有班级和关联继续使用原 ID。

归档学期先只读查看。点「更正班级资料」或「更正名单」后进入编辑，停用班的名单仍只读。跨学期同名班按 ID 区分。学期或班级身份版本变化时，请返回目录核对原班。名单版本变化时，按学生 ID 并列显示服务器当前值和草稿，可逐行选择，再以服务器当前名单为基准重新预览并确认。建班成功回包中断时，可先按原请求编号只读找回本人的班级 ID。名单若只核对到服务器当前值一致，界面按实际核对结果提示。

准备草稿期间，学生继续使用原启用学期；正式启用草稿后，从日常班级入口即可打开已准备的原班和名单。部署先更新 KV，再更新 Console。本功能沿用已有回执表，无新增数据库迁移，旧网页指定学期的班级和名单入口保持兼容。

## 指定学期的教学安排与师资

从「班级与教务 → 学期管理」选中学期，点「教学安排与师资」。草稿的启用前检查及指定学期的班级详情也有入口。页头同时显示办理学期及状态、全校当前启用学期。归档学期可先核对授课、任课和岗位，点「更正安排」后才可提交。

### 编辑整班规则

在「教学安排与师资 → 班级全科」选定行政班后点「编辑整班规则」，当前学期班级详情也可直达。逐科选择随班、走班或不开设，并独立维护必修属性。四种授课方式预设先填到草稿，保留已开科目的必修属性。筛选只影响显示。

预览时选中一科，即可对照学校当前安排和草稿，并核对哪些教学班将解除与本班的来源关系。已停用的教学班也会列出，每条关系都显示仍保留的来源班。窄窗可在科目列表与详情之间往返，底栏汇总整份方案尚待核对的项目。清空本班全部开科另行确认。若他人先改了来源，需按新预览重新勾选。

遇有效随班任课或必修走班缺组，可按班科去办理，返回保留草稿并核对学校当前安排。旧网页「行政班授课规则」使用同一提交保护。缓存旧页面没有新版预览时提示刷新。断线后可用原编号只读核对本人回执，服务器当前值另行显示。

## 建年级并开班

管理员选择学校后，点击「新建行政班」。当前启用学期没有年级，或需要补建年级时，在同一个窗口点击「新建年级」，填写名称和代码。Console 收到本次创建回执并刷新年级后自动选中对应年级。可继续填写班名和代码，按需调整「允许学生自行选择此行政班」。年级代码在学期内唯一，班级代码在该学期的教学空间中唯一。

年级重码时可更换代码。创建回包中断后点击「核对结果」，Console 按原请求编号查询。学校暂未记录该请求时，可用原编号重试。另一个管理员创建的同名或同码年级不会被自动选中。填写期间切换学期时，需刷新并核对后再提交。

点击「创建并录入名单」后，Console 按 KV 返回的班级 ID 定位新班，打开学生名单。建班和名单保存分两步生效，关闭名单窗口后，已创建的班级仍可从班级列表进入。建班回包中断时，「重试确认」沿用原请求，KV 返回首次成功的班级 ID。切换学期或失去学校管理权限后，旧表单无法再写入。

升级 KV 时需应用 `20261121000000_admin_class_creation` 和 `20261121020000_current_grade_creation` 数据库迁移。它们保存建班和建年级的原请求回执。

## 按年级批量开班

## 当前学期行政班维护

## 教室设备运行报告与诊断导出

从「教室设备 → 具体大屏 → 运行报告」读取这台原生设备最近 20 份结束报告，并分开核对设备当下执行。服务端每台设备保留 30 天内最多 200 份。报告分别呈现采样和总时长、原始 dBFS、估算 dB(A) 与各自覆盖；缺来源、缺样、参考失效和时钟跳变均有提示。班级场次及其照片、退出记录以入库时确认的学校、学期和班级为准。缺归属的旧报告只在原设备历史仍具权限时可查看。换机或撤销后，按原班保存的场次仍可从学校自习查阅。

从「现场处置」进入时，只用 KV 记录的原设备及采样会话定位此次恢复的结束报告。仍在采样或尚未上报时可先查设备现状。历史处置回执若没有该会话编号，不自动选择其他报告。

在「教室设备 → 导出原生诊断…」确认筛选条件、匹配／已加载／实导数量、观测时间、过期提示和下一页情况，再选择位置保存 JSON。最多写入已加载的 200 台。文件含服务 origin、版本、状态和业务编号，排除设备或班级名称、搜索词、凭据、路径、日志、音频及照片。浏览器自身的故障包仍从网页采集。

运行报告首屏显示有效采样、总时长、覆盖率和采样警示。「设备当下状态」可展开查看当前执行和原生设备编号。选中有原班归属的报告，可在同一个窗口打开「本场照片与退出记录」。窄窗查看单张后可返回原记录行，再返回原报告。班级详情仍可直接查询记录。

先更新 KV，再更新 Console。本轮复用现有数据和权限，无新增数据库迁移，旧网页和教室端无需升级。真实联调用 `--device-run-reports`，白名单专项用 Console Smoke 的 `--device-diagnostics-checks`。

## 教室考试模式与方案放映

从「教室设备 → 具体大屏 → 考试与放映」进入，也可从班级大屏卡直达。工作页固定显示学校、班级、屏名、绑定编号和原生设备。分别核对环境切换和方案放映状态。进入考试会联动 ClassIsland 和 ExamAware 的运行与登录自启动，先正常保存现有录制，再暂停后续自动录课，原录课计划保留。返回日常前请在教室结束 ExamAware 放映，保存并关闭未保存的编辑器内容。

选择 UTF-8 `.ea2` 或 `.json` 文件，最大 24 KiB，先投递给目标设备校验。核对设备返回的考试名称、每场起止和提醒，再点名该屏确认开播。界面分别显示设备回报切换完成、方案校验通过、启动已受理和本次放映就绪。本次就绪及结束取同一播放器会话的近期观测；观测过期时提示核对现场。尚未取得开始许可的操作可取消。回包中断先查询原请求，在当前登录会话可按原请求编号重试。从同一大屏重新进入可读服务器上的任务和设备观测。

一次返回日常成功后，上一场放映仍可在历史查到。后续只切换考试环境的教室，成功核对本轮没有投递或启动的方案后，可按独立的环境授权申请返回日常。已有开播授权时仍须核对本次会话结束，设备始终执行现场阻断检查。

上线先更新 KV，再更新 Console。沿用 NPEP 0.4/0.5 的现有授权、模式和方案数据，无新增数据库迁移。旧网页继续访问同一任务。隔离验收用 `--exam-workbench-db` 和 `--exam-workbench`，后者需要构建 NPEduTools 的 ExamAware TestHost、桥接插件和本机 ExamAware 1.5.2。可用 `NP_EXAM_AWARE_SOURCE` 指定源码目录，也可用 `NP_EXAM_AWARE_ELECTRON`、`NP_EXAM_AWARE_ARCHIVE` 指定本机构建的 Electron 和归档。验收实际打开并关闭播放器，ClassIsland 登录任务、自启动及录制效果使用隔离模拟，正式打包版未覆盖。证据默认在 `.artifacts/exam-workbench/final`。

## 全校作业录入设置

在「班级与教务 → 作业录入设置」编辑本校快捷词与大屏快捷截止时间，学校尚未启用学期也可办理。快捷词支持分组排序、适用学科与换行，空表表示关闭。截止时间保留 1–8 项。试用区可切换学科试插正文，也能选基准日核对日期。基准日若也是指定星期，截止时间算到下一周的同一天。恢复默认只改当前分区的草稿。教师端与大屏刷新后读取新配置，已发布作业保留原正文和截止时间。

Console 一次保存所有已修改分区。网页的「教师分配」保存快捷词，「大屏设备」保存截止时间。两个分区各自检查版本，同一区的并发改动需要核对当前值，任何冲突都使 Console 本次提交整批零写入。失效学科引用留在草稿以便修正。回包丢失可按本校本人的原请求只读核对，再读取学校当前值。

先应用 KV 数据库迁移 `20261122090000_school_homework_settings_receipt`，发布新版 KV 后更新 NPClassworks 网页与 Console。升级中的旧缓存管理页面如果没有版本，保存会提示刷新或重新打开。教师和大屏的配置读取格式保持兼容。隔离回归用 `--homework-settings-db` 和 `--homework-settings`，证据默认在 `.artifacts/homework-settings/final`。
