# 学校管理网页迁移清单

## 学校管理总览与待办

学校管理员选择学校后进入「学校总览」，也可从左栏随时返回。「管理待办」按当前启用学期列出学校配置、具体班级和具体大屏。建年级、单班或批量开班沿用「新建行政班」。对未登记首屏的班级，点击「前往登记」进入原登记区，再由管理员确认登记。对待接入或待上报的大屏，点击「定位大屏」按原班级和绑定 ID 打开对应入口。返回总览时重新读取学校服务。

「大屏状态」分别显示网页首次登录和值守心跳，以及 NPEduTools 配对和有效上报。Console 登记首屏后会出现 NPEduTools 接入待办，登记网页账号也会独立显示首次登录待办。终端成功上报后，同一绑定的首次上报待办消除。KV 保留最近一次有效上报的时间，终端重开 Host 会话仍可查阅该记录。旧数据若已在升级前丢失上报证据，显示「待核对」。原班重新启用后，既有规则判定旧 NPEduTools 授权已失效时，待办提示现场重新配对。

当前学期的班主任、年级职责、本地教师账号、走班和网页大屏值守待办可在 Console 办理。暂无启用学期的待办可打开桌面学期管理。强制启用及单独归档沿用原网页学校管理入口。网页地址取自 KV 的 `FRONTEND_URL`。地址未配置时，Console 显示原网页办理提示。无需另填监控凭据。

上线先部署 KV 并应用迁移 `20261121040000_npep_device_last_report`，再更新 Console 和网页。旧网页仍可查询指定学期。新接口位于 `/api/v2/admin/schools/:schoolId/management-overview/current`。

## 批量配置随班授课科目

在批量开班结果、班级详情，或暂无随班科目的「任课分配」窗口点「配置授课科目」。批量开班结果会预选本批新班，其他入口预选当前班。可以勾选同年级启用班和本校已有学科，在预览中逐班逐科核对，也可取消任意一个组合。缺少学科时点「新建学科」，保存后会选中服务器确认的新学科，并保留已勾选的班级和学科。继续预览并确认后才写入当前学期的授课规则。

Console 只补设随行政班授课的规则。新增项沿用非必修默认值，已有随班规则及其必修信息原样保留。走班规则、走班来源、任课、名单和访问权限也会保留。所选项目冲突、班级变化或切换学期时，KV 不写入本批。重发相同配置不会新增重复规则。若其他管理员已改过某一项，可在对应行对照预览和当前记录，再重新预览。回包中断时先只读核对实际规则。在同一次登录中关闭窗口后，可从同一学校、学期和入口班级重新打开「配置授课科目」，继续核对原选择。成功后可选择班级与学科进入任课分配，返回总览重新核对缺教师待办。

开设当前学期走班课程时，使用「走班教学班」。全量替换授课规则和其他学期管理仍在网页。部署先更新 KV，再更新 Console，本轮无新增数据库迁移。本地 Windows 联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --current-subject-setup`，截图默认写入 `.artifacts/current-subject-setup/desktop-live`。

## 学校学科目录

选择学校后，在「班级与教务 → 学科目录」按名称或代码查找，创建或编辑名称、本校唯一代码、类别和显示顺序。目录全校共用，无启用学期也可办理。编辑沿用学科 ID，各学期的授课规则和任课仍引用原学科。

代码重复时可就地修改。另一位管理员先保存时，草稿保留，Console 显示学校当前值，采用当前版本后可重新提交。创建回包中断时，Console 在当前登录会话保留请求编号，可关闭并重开目录继续只读核对。回执只归原学校与账号。返回开科前如遇学期切换，已建学科保留，请选新学期的班级继续。

旧网页可继续维护学科。删除和合并学科目录项目仍按原流程处理。部署新版 KV 时先应用 `20261121050000_school_subject_creation`，再更新 Console。Windows 与隔离 PostgreSQL 回归可用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --school-subjects`，截图默认在 `.artifacts/school-subjects/desktop`。

## 当前学期行政班任课

在「学校总览 → 管理待办」找到某班某科缺任课教师，点「分配任课」。也可在启用的班级详情点「任课分配」。左侧选择科目、教师和班级，右侧逐班对照当前任课与预计变化。并发修改时会定位到需要重新核对的班级。

新增时选择本校已有教师及主讲或协同身份，可以同时勾选同年级、该科目随行政班授课的其他启用班级。预览列出逐班变化和当前安排。有主讲冲突或预览已过期时，整批不写入。可以取消有冲突的班、选择协同，或单独修改原关系。提交回包中断时，Console 先只读核对服务器当前安排。返回总览后重新读取待办。

新增或调整任课可能授予或提升班级成员权限。修改为协同或移除任课时，已有班级成员权限保留，其他科目和职责授予的访问照常有效。本地教师账号和当前学期走班任课另有桌面入口。上线先更新 KV，再更新 Console，本轮无新增数据库迁移。

本地联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --current-teaching`。使用隔离数据库、Windows Console 和 Edge，截图默认写入 `.artifacts/current-teaching/desktop-live`。

## 当前学期走班教学班

从「班级与教务 → 走班教学班」按年级、学科或缺教师筛选，打开或新建教学班。在「学校总览」点「核对走班来源」会定位到缺覆盖的行政班或需要核对的教学班，点「分配走班任课」会进入对应教学班的任课编辑。

开设或补来源时，选择同年级启用行政班，填写教学班名称、唯一代码和是否允许学生自行选择。预览逐班列出新增、保留和移出，既有同科教学班和随班任课可一起核对。同一行政班可同时作为多个同科教学班的来源。若某班仍有有效随班任课，可打开该班任课处理，返回原走班草稿后重新预览。移出一条来源会保留原授课规则和其他教学班，最后一条覆盖移除后会出现缺覆盖待办。

确认时 KV 在同一事务内复核学期、权限和预览依据，保存目标教学班、来源以及涉及班级的该科规则。保留必修信息、其他科目及既有任课和权限。并发变化时整次零写入。若保存回包丢失，Console 先按本次请求编号只读核对，并按服务器确认的教学班 ID 返回列表。任课另行保存，沿用任课、来源班主任职责和既有成员关系分别生效的权限。当前学期的停用、恢复和改科转到「年级教学安排」。历史学期和全量授课规则维护仍走旧网页。

上线先部署 KV 并应用 `20261122010000_current_course_group_receipts`，再更新 Console。Windows、学生网页和隔离 PostgreSQL 联调使用 `--current-course-groups`，证据默认在 `.artifacts/current-course-groups/desktop`。

## 当前学期按年级调整教学安排

从「班级与教务 → 年级教学安排」选择年级和科目。也可从「走班教学班」选中目标后点「停用或改科」。逐班对照当前和调整后的授课方式、必修设置、可选走班和任课。可多选行政班，逐班调整，在同一份方案中加入走班停用、并入、恢复、改科和任课，然后统一预览并保存。从总览可继续办理留待分配的任课。

停用和恢复沿用原教学班 ID，并单独显示任课、成员权限、邀请和发布影响。没有任何发布目标或任课历史时，核对来源与权限后可原 ID 改科。已有发布（含历史版本）或任课记录时，按新科目另开班使用新代码与新 ID，可在同一方案明确停用原班。原记录保留在原编号，任课与独立访问不会自动转给新班。现有桌面任课和网页入口移除或更换走班教师时也会保留失效记录，仍能核对改科限制。升级前已物理删除且没有其他证据的历史无法重建。学生选课保存在浏览器，本页展示各班的可选项变化。失效选择由学生重新确认。

KV 在同一事务核对权限、当前学期与逐项确认的来源、规则、任课、发布和权限影响。发生相关并发变更时整份零写入，Console 定位变化并留住草稿。回执中断后按学校、操作者和本次请求只读核对。

上线先部署 KV 并应用 `20261122050000_grade_teaching_plan_receipts`，再更新 Console。隔离 PostgreSQL 回归使用 `--grade-teaching-plan-db`，Windows Console 与 Edge 学生和教师链路使用 `--grade-teaching-plan`。证据默认保存在 `.artifacts/grade-teaching-plan`。

## 学校自习管理

在「班级与教务 → 学校自习」按年级和日期查看当日实际安排，默认打开本周。并列列出日常和考试时段、来源和班级。窄窗从当天列表进入班级详情，返回时保留日期、班级与焦点。跨午夜的场次保留原开始日，结束前仍会出现在次日。日常由教室 ClassIsland 的学校时间判断，考试用 Windows 的北京时间。

「编辑年级安排」和「编辑本班安排」可以分别维护日常或考试的每周时段、生效和截止日、指定日期停排与调休。班级可独立设置、关闭或恢复继承。仅当班级和年级均未提供自习策略时，才可能沿用旧版定时噪音安排。预览完整列出受影响的班级，也列出因独立或关闭而保持原状的班。保存只改明确编辑的时段或启用规则。旧网页修改了相关依据时，本次零写入，保留草稿并定位变化后重新预览。排期丢回包可以按同一请求只读核对。

从本班详情打开「座位图与逐屏状态」可预览、发布、替换、撤回，也可从仍有图片的历史版本重新发布。图片归自习所在班级，即使作业来自其他班。逐台大屏按绑定编号列出配置版本、Host 下载、展示端应用与最近打开的时间。前屏打开旧图时，下载的新图在关闭再打开后可见。旧图或过期证据不会计为已应用新图。同班后屏缺回执时单独显示待核对。座位图使用独立的发布回执。「本日场次与回执」从所选日期和班级打开报告及教室回执。

本班详情的「监测策略」可以核对生效来源，编辑本班独立策略或进入年级监测。噪音阈值可用 dBFS 或现场校准的估算 dB(A)。高线持续时间同时用于超限提醒和拍照判定。年级保存前逐班核对继承、独立和关闭，原排期、作业来源和展示设置随策略保留。把继承班改为独立设置会停止整套策略的年级继承。定时自习与符合条件的手动自习可触发拍照，摄像头继续在教室现场选择。

本班「照片与退出记录」按日期及原班级查询。进入「本日场次与回执」后也可从每台设备的已上传报告打开同一记录页，按学校、学期、班级、设备和场次片段核对。学校配置、教室应用、采集信号及已存照片均有独立证据，退出记录可以没有图片。只有本校具有有效 OWNER 或 ADMIN 会话的账号可以列出、预览、下载或删除；下载由管理员选定位置，查看、下载和删除沿用服务端审计。在线保留期缩短会提前照片和退出记录的到期时间，延长保留期沿用既有记录原来的到期时间。备份副本的保留按部署处理。旧网页保留原有监测、报告及照片入口。

先部署 KV，再更新 Console，无新增数据库迁移。旧网页和当前教室端协议继续兼容。Windows Console、实际旧网页、隔离 PostgreSQL 与 NPEduTools Host/WPF 联调用 `--school-study`，专项数据库用 `--school-study-db`。证据目录默认是 `.artifacts/school-study`。

## 开学组织导入

从「班级与教务 → 开学组织导入」选择本校已启用学期或草稿及一个年级。从「学期管理」选中草稿后点「导入草稿组织」会带入该学期。可打开旧组织 JSON、载入七班制示例、从 Excel 粘贴制表符分列的数据，或直接编辑行政班、学科规则、教学班和来源。Excel 弹窗列出对应表头。页头有已选学校、学期和年级。载入 JSON 保留已选年级，年级尚为空时可使用文件声明；文件与目标不匹配时并列显示两边的值，要求重选目标或换文件。旧文件中的认证、学校设置与启用指令不进入桌面写入。

「预览导入差异」逐项列出现状与导入后结果。新增学科全校可见；已有学科继续使用原 ID、名称、类别及顺序。默认补充，保留未列出的班、授课规则及来源。只有对指定班级选择「按表替换」才会移除预览列出的关系。同码停用班、跨年级重码、与现有任课冲突和有历史的走班改科在预览中阻断。确认时复核当前状态。并发改动使整批零写入，表格可保留并定位复核。丢回包只按本人原请求查询服务端回执。

当前学期或草稿导入完成后，都可点「继续分配教师」，沿用回执中的学校、学期和年级。也可从回执进入任课或草稿的「启用前检查」。导入仅写教学组织，草稿保持准备中。首次建校和归档学期维护沿用旧网页入口。

上线先应用 KV 迁移 `20261122060000_school_organization_import_receipts` 并更新 KV，再更新 Console。隔离 PostgreSQL 回归用 `--organization-import-db`；Windows Console、实际 Edge 旧网页、学生和教室联调用 `--organization-import`。两种模式都由 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录>` 运行，证据默认在 `.artifacts/school-organization-import`。

## 本校教师账号

在「班级与教务 → 教师账号」可按姓名或短账号搜索、新建、停用和恢复普通本地教师。学校尚未启用学期或没有班级时仍可办理。个人 PIN 模式可重置 PIN，学校通用口令模式只建短账号。普通教师批量建号、OAuth 邮箱邀请和班级访问分配见下节。所有者也可从具体教师打开「账号与权限」，按原账号授权。

也可在任课、班主任、年级组长的教师选择区点「新建教师」，按已确认的账号 ID 回选并保留上一页草稿。新建仅授予普通学校成员身份，任课和职责等待管理员单独确认保存。同名教师按短账号区分，本校重码时可核对原账号或改用其他短账号。提交回包中断时按本次请求编号只读核对。

「学校总览」可按账号定位已停用仍有任课或有任课但未首次登录的教师。详情分开显示账号状态、真实登录时间、当前学期任课和职责。停用或重置 PIN 会退出旧会话，恢复沿用原账号；任课、岗位和班级成员关系保留。首次登录提醒只在教师实际登录后消除。

上线先部署 KV 并运行迁移 `20261121060000_school_teacher_account_receipts`，再更新 Console。Windows 与隔离 PostgreSQL 回归使用 `--teacher-accounts`，证据在 `.artifacts/teacher-accounts/desktop`。

## 开学教师名册与班级访问分配

从「班级与教务 → 教师账号 → 批量导入与分配」打开工作台，也可以从「开学组织导入」结果继续。选择当前学期或草稿学期及年级后，可粘贴 Excel、打开旧教师分配 JSON 或搜索已有教师。旧文件声明的学校、学期或年级与当前选择不一致时，窗口会并列显示两边的目标，保留原教师表，待更换文件或重新选定范围。只建本地教师账号时，可以不选学期。个人 PIN 模式下只为新账号设置初始 PIN，重导会保留已有账号的凭据、状态和会话。通用口令模式只需短账号。邮箱模式可分配给已验证的账号，也可预分配给待登录邮箱。无唯一可信身份时核对具体行，登录认领以学校允许的登录方式和服务器记录为准。

可为行政班与走班教学班设置教师、助教、只读，也可明确移除直接访问或撤回待认领邀请。预览按教师和教学空间显示原角色、计划角色及影响。任课和岗位职责各自生效，移除一条直接成员关系后仍可查看由职责或任课产生的访问。表外关系保持原状。降级、移除和撤回都要确认对应对象。管理员、所有者、特殊角色和归档学期仍用原入口。

保存时 KV 在同一事务内复核学校权限、学期和预览涉及的身份及关系。并发变化时整批零写入并标出需要核对的行。回包丢失后按本人原请求只读查回。结果按教师或班级核对直接成员、访问来源和待认领邀请。当前学期可从已确认的目标班继续办理任课。

上线先应用 KV 迁移 `20261122070000_school_teacher_allocation_receipts` 并更新 KV，再更新 Console。隔离 PostgreSQL 用 `--teacher-allocation-db`，Windows Console、Edge 旧网页与教师登录联调用 `--teacher-allocation`。桌面复验在控制台提示后，用原生文件对话框依次打开三份路径已打印的测试 JSON。证据默认在 `.artifacts/teacher-allocation`。

## 学校管理账号与权限交接

选中学校后从左栏「账号与权限」进入，无需启用学期。所有者及管理员可核对本校账号名册。导出的无密 CSV 包含全校账号、身份、角色、登录状态、最近登录和当前学期的直接教学空间，不受页面筛选影响。只有所有者可以新建管理账号、变更管理权，或为其他管理账号重置 PIN、停用、恢复和注销本校访问。短账号已存在时按账号身份核对后另行授权。本人改 PIN 需验证原 PIN。

新授权须用适用于该身份的方式重新登录。既有教师通用口令会话不会取得新增管理权，独立任课、岗位和直接成员关系仍按原规则生效。管理权包含查看全校自习照片的权限，收回后立即按现有会话重新验权。角色变更、停用登录和注销本校权限各自有影响预览。学校仅有一名所有者时可以继续工作。最后一名可用所有者退出前，要先确认另一位已启用的所有者在获权后成功登录。Console 与网页登录都可取得 OAuth 登录证明，和本地 PIN 证明分别显示。跨校成员角色按各校现行授权核对。

保存回包中断时先按原请求只读核对。暂未找到回执时可明确选择按原编号重试，服务器会重新核对预览。需要 PIN 时须重新输入，只有服务器明确确认重试实际写入才可交付该次输入的 PIN。部署前先应用 KV 迁移 `20261122100000_school_management_authority`，再更新 KV、NPClassworks 网页与 Console。首次建校、服务器恢复密钥及既有登录方式设置仍可在网页办理。隔离 PostgreSQL 回归用 `--management-accounts-db`，实际 Windows Console 和 Edge 联调用 `--management-accounts`，证据默认在 `.artifacts/management-accounts`。

## 学校管理员 OAuth 桌面登录

在登录页填写 KV 地址后，点击「使用浏览器登录」。服务器配置多个提供方时先选择。浏览器确认页显示服务器、提供方及本窗口的核对码，点击继续后完成 OAuth 认证，再返回 Console。短账号和 PIN 登录继续可用。登录后仅列出此会话当前具有 OWNER 或 ADMIN 权限的学校，单校直达总览，多校按校名和角色选择。

原窗口接收并确认本次领取后，KV 激活该会话并记录登录证据。浏览器完成但尚未领取、取消或领取回包中断都不形成有效接任登录。确认已提交但响应中断时，Console 凭原会话只读核对学校。授权变化按学校分别核对，较早的认证结果无法继承随后授予的新权限。

先更新 KV，再更新 Console。使用上轮 `school_management_authority` 表，本轮无需新增数据库迁移。身份提供方继续使用 KV 原有固定回调。多实例代理沿用现有 OAuth 会话同实例处理安排。隔离验收用 `--desktop-oauth`，证据默认在 `.artifacts/desktop-oauth/acceptance`。

## 当前学期教师职责

在「学校总览」点「办理班主任」或「办理年级组长」，按学校、学期及对象 ID 打开对应编辑区。指向教师的提醒会定位到该账号。也可以从「班级与教务」的班级详情打开「班主任」，或从年级标题旁打开「年级组长」。

按姓名或账号搜索本校教师，对照当前和保存后的安排。交接时逐行决定原负责人转为协同班主任或副组长，还是卸任。原来存在多位主要负责人时，全部列出，预览前需把各人去向确定，并保留至多一位主要负责人。预览中的岗位联动提醒沿用现行学校设置。

保存时 KV 核对当前学期、学校管理权限、对象状态、教师归属和版本。并发修改时零写入，Console 显示服务器当前安排并保留草稿；采用当前版本后重新预览。回包中断时先只读核对，在同一次登录中可重开同一对象继续核对。返回总览会重读待办并恢复筛选与位置。

职责、任课及班级成员权限独立生效。班主任和协同班主任可管理本班、查看相关走班，年级组长和副组长可管理本年级教学空间。卸任不会删除原任课或成员关系。旧网页继续承接历史学期、岗位联动规则维护和原职责办理入口。先部署 KV，再更新 Console，无新增数据库迁移。Windows 与隔离 PostgreSQL 验收使用 `--current-staff`，截图在 `.artifacts/current-staff/desktop`。

## 为未匹配大屏安排新班

在「学期启用结果」选中仍绑定原班的大屏，或在「学校总览」打开该屏的待安排事项。表单按绑定编号读取原学期和原班，按年级、班名或代码搜索当前启用学期的行政班。选中班级后先核对该班已有大屏，再确认安排。任何现有学校管理员都能接手，原启用回执和个人安排回执仍分别归各自操作者。

保存沿用原大屏编号、网页账号及 PIN，旧网页会话失效，重新登录后可继续使用该账号。迁入屏按现有流程现场重新配对；目标班原有大屏保留绑定和凭据。结果区分待配对、待首次有效上报和已上报。原启用结果仍记载当时没有匹配，另显示后来安排和当前设备状态。

目标班、已有大屏、当前学期或原绑定已变化时，KV 拒绝旧确认。回包中断可按原请求只读核对，服务器未查到前保持原编号。已通过旧网页改绑且能核对当前归属时，Console 显示服务器观察到的目标。旧网页的大屏管理入口保留。

上线先应用 KV 迁移 `20261122040000_term_screen_placement`，再更新 Console。本地验收使用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --term-screen-placement`；数据库回归使用 `--term-activation-db`。

## 学校审计记录的退役条件

使用本地学校管理账号登录 NPEduConsole，选择学校后即可查看审计记录。即使学校尚无启用学期、班级或大屏，也可以查阅。该入口读取 KV 的学校 `AuditLog`。每次查询时，KV 都会核对当前账号在该校的 OWNER 或 ADMIN 权限。

| 管理员要做的事 | Console 中的对应操作 |
| --- | --- |
| 找出某天失败的操作 | 选择操作来源、类型、结果及本地起止日期，读取选中日期全天的记录。 |
| 查更早的记录 | 按时间倒序浏览，点击「加载更多」查看下一页。点击「刷新」或「应用筛选」都会从第一页开始。 |
| 核对一条记录 | 查看操作者或大屏、时间、操作对象、请求路径、HTTP 状态、来源 IP 和脱敏参数。旧记录缺少的字段按缺失显示。 |

**网页入口目前保留。** 新版 KV 与 Console 支持 OAuth 和本地管理账号登录。正式退役 `section=audit` 网页导航前，仍需确认使用该入口的管理员已用实际学校提供方完成桌面登录，并处理指向旧地址的链接。OAuth 管理员无需新增本地口令。

## 新学期草稿、检查与正式启用

从「班级与教务 → 学期管理」核对正在使用的学期和准备中的草稿。学校总览「暂无启用学期」可直接打开此页。已有草稿可直接检查，学校尚未建立任何学期时使用页面上的网页初始化入口。

从当前启用学期建立草稿时填写学年、学期序号、名称和日期。预览与实际复制使用同一继承计划，默认复制教学空间成员权限、有效任课及有效职责，未认领的 OAuth 邀请默认不选。预览可逐个核对走班来源、任课和年级或班级职责。取消任课仍可能通过单独继承的成员权限保留教师访问。学生名单需另行准备。

来源配置或当前学期发生变化时，服务端重新核对，原表单保留。若本次成功回包中断，Console 先按原学校、操作者及请求编号查询回执。只有服务端认领的草稿 ID 用于打开本次建立结果。同学年同学期已存在时，也可独立打开已有草稿。

启用前检查区分阻断、一般提醒与大屏影响。按绑定编号逐台核对原班、默认同码匹配的新班及无匹配状态。可确认的既有 NPEduTools 配对在默认改绑后需现场重新配对。创建和查看草稿不会改动正在使用的学期、大屏绑定或原生配对。

在「启用前检查」核对目标草稿全名、将归档的原学期、教务阻断和逐台大屏影响后，点击「启用此学期」并确认。KV 重新核对操作权限、目标范围和逐台绑定；依据有变化时本次零写入，并列出变化。启用、归档和实际改绑一次提交。回包中断时先按原学校、账号及请求查询回执，也可从学期管理重开本人上次的启用结果。强制启用及单独归档仍走原网页。

结果页显示已启用和已归档的学期、改绑台数和待处理项。已改绑的 NPEduTools 大屏按现场流程重新配对，收到该屏的首次有效上报后才消除对应待办。无匹配的屏继续绑定原班，待管理员安排新班。归档会令绑定在原启用学期的原生凭据失效，包括未改绑的屏。网页大屏值守状态仍由其自身的回执判断。返回总览重读班级和待办。

部署先应用 KV 迁移 `20261122030000_term_activation_receipts`，再更新 Console。同步更新 NPClassworks，可让网页提交时携带检查版本并提示具体变化。已有网页客户端仍能启用，KV 会在写入时重新核对。本地联调用 `node tests/live-kv.mjs <KV 工作副本> <PostgreSQL bin 目录> --term-activation`，独立数据库回归使用 `--term-activation-db`。

上线先部署 KV 并应用 `20261122020000_term_preparation_receipts`，再更新 Console。Windows、实际 Edge 学生端及 NPEduTools 原生互联联合验收使用 `--term-preparation`，产物默认在 `.artifacts/term-preparation/desktop`。

## 当前学期的行政班学生名单

使用本地学校管理账号选择一个行政班后，打开「学生名单」。可逐行增改、移出和排序，也可粘贴 Excel 两列或纯文本名单，选择追加或替换。预览并列显示原名单和保存后的姓名、学号、位置，确认后生效。无大屏的班级也可以办理。

有学号的行按学号匹配，保留前导零。无学号的行按未编号学生的姓名匹配，遇到同名需要逐行核对。改名或改学号可直接编辑现有行，以保留学生 ID。移出学生后，已登记的历史考勤仍保留原 ID。

管理员和大屏共用同一份名单修订号。遇到并发修改，Console 保留草稿，读取当前名单供核对。保存回包中断时也会先读取服务器现状。新版 KV 会在写入时检查本班学期是否仍在使用，切换学期后需重新选择班级。

网页版仍承接指定其他学期的名单维护。

## 建年级并开班

管理员选择学校后，点击「新建行政班」。当前启用学期没有年级，或需要补建年级时，在同一个窗口点击「新建年级」，填写名称和代码。Console 收到本次创建回执并刷新年级后自动选中对应年级。可继续填写班名和代码，按需调整「允许学生自行选择此行政班」。年级代码在学期内唯一，班级代码在该学期的教学空间中唯一。

年级重码时可更换代码。创建回包中断后点击「核对结果」，Console 按原请求编号查询。学校暂未记录该请求时，可用原编号重试。另一个管理员创建的同名或同码年级不会被自动选中。填写期间切换学期时，需刷新并核对后再提交。

点击「创建并录入名单」后，Console 按 KV 返回的班级 ID 定位新班，打开学生名单。建班和名单保存分两步生效，关闭名单窗口后，已创建的班级仍可从班级列表进入。建班回包中断时，「重试确认」沿用原请求，KV 返回首次成功的班级 ID。切换学期或失去学校管理权限后，旧表单无法再写入。

升级 KV 时需应用 `20261121000000_admin_class_creation` 和 `20261121020000_current_grade_creation` 数据库迁移。它们保存建班和建年级的原请求回执。

## 修改当前学期的年级名称

选择学校并打开「新建行政班」。在「所属年级」选中目标年级，点击「修改名称」。保存后仍选中这个年级，可以随时关闭窗口。已有班级和名单的年级也能改名。年级 ID、代码、排序、所属学期以及班级和学生关联保持原样。

多人编辑发生冲突时，Console 保留输入并显示学校的最新名称。回包中断时先读取该年级，提示学校当前名称是否与本次输入一致。启用学期变更后，需重新载入并选择年级。改名入口需要新版 KV 的年级版本字段和当前学期改名接口，无需新增数据库迁移。网页继续承接指定其他学期的新建与编辑，以及年级代码和排序调整。

## 按年级批量开班

选择学校并打开「新建行政班」。在「所属年级」选中已有年级，再点击「批量开班」。输入起止编号和可调整的名称、代码前缀，例如用高一年级生成 1 至 12 班。点击「生成预览」，可逐行修改名称、代码及学生自选设置；一次可创建 1 至 100 个班。

点击「核对」可提前查看代码冲突。保存时 KV 重新确认学校权限、启用学期、目标年级和代码占用。整批成功或整批不建班。发现冲突后会定位到相应行和字段，保留整批草稿。可用「定位首个问题」返回该字段，修正并重新核对后保存。回包丢失时点击「核对结果」，Console 按原批次编号查询管理员自己的回执。在同一次登录中关闭建班窗口后，重新打开可继续核对。若服务器暂未记录，可用同一编号重试未改动的草稿。

成功后任选一条服务器回执打开名单。Console 重新启动后，班级也可从常规班级列表找到。上线前需应用 KV 的 `20261121030000_current_class_batch_creation` 迁移。旧网页仍可为指定学期批量建班。

## 当前学期行政班维护

选择学校和班级，在班级详情点「维护班级」。可以修改名称、代码和学生自选设置。代码在同一学期的教学空间内唯一。版本冲突时，先点「核对服务器班级」，查看服务器名称、代码和状态，再决定是否保存保留的草稿。保存并刷新后，Console 按原班级 ID 选中该班。

点「查看停用影响」，核对学生、大屏、任课及正在生效的作业或通知等关联。读取失败时可以重试。KV 会在写入时核对当前启用学期、权限、班级版本和预览的关联内容；关联变化后，必须以新摘要为准再次确认。停用后在班级目录勾选「仅已停用」，选中原班并点「重新启用」。重新启用会回到正常列表并选中原班，原名单、大屏绑定和历史发布记录仍对应原 ID。

停用期间，现有网页大屏访问该班会被 KV 拒绝。重新启用后，未过期、未另行重置的原网页大屏令牌可继续使用。NPEduTools 按既有数据库规则处理：停用会推进大屏绑定版本，并使旧设备配对授权失效。重新启用保留原大屏与设备历史记录，教室端需重新配对。旧网页仍可管理指定学期。本次升级需要部署支持行政班维护接口的 KV 和 Console，无新增数据库迁移。

## 给新班准备第一台教室大屏

在「班级与教务」选中当前学期的新班，点击「准备教室大屏」，也可从学校总览的缺屏待办直接进入。收到登记确认后，Console 会按返回的大屏 ID 打开「配置口令接入」。本班已设管理口令时可直接沿用。首次设置时，在此预设班级管理口令并确认开放。现场在 NPEduTools 的「学校互联」选择对应学校、班级和大屏，输入班级管理口令。终端上报后，可从「教室设备」核对这台大屏的接入状态和最近记录。

登记成功后可以稍后开放原生接入，也能转到「网页账号与值守」给同一台屏补网页登录账号。有停用大屏的班级可在「大屏账号与值守」勾选「只显示已停用」，核对原绑定后恢复。原生首屏登记回包中断时先刷新列表核对。

## 教室大屏账号与值守

从「学校总览」的网页大屏待办打开对应大屏，也可在班级详情点「网页账号与值守」，或在「教室设备」按屏名、班级或编号定位。办理页显示所在年级、班级及绑定编号，并分别读取网页登录、当前心跳及待上传数量，以及 NPEduTools 配对和有效上报时间。心跳来源已变化时，旧时间只作为历史显示。

为已登记大屏补网页短账号和 PIN 时沿用原编号。增加一台屏时选择「登记同班另一台大屏」。改名保留两种会话。短账号的大小写或首尾空格变化无需保存。实际换短账号、重置 PIN 或解除浏览器绑定会结束旧网页会话，已配对的 NPEduTools 仍可上报。此前的一次性配对码、依赖旧网页凭据版本的待确认换机，以及使用网页 PIN 授权但尚未执行的停止定时噪音请求，在使用时会重新核对凭据版本，可能需要重新发起。调班会结束旧网页会话并使已配对的 NPEduTools 授权失效。整屏停用期间网页无法值守，恢复后原网页凭据可继续使用，已有原生配对须到教室重配。学期启用后未匹配的大屏仍走「为未匹配大屏安排新班」。

「查看同步情况」提供刷新网页数据、重载网页和逐条回执。「已确认刷新数据」来自网页重新读取服务器后的成功回执。旧版网页缺少实际读回的证据时显示「已收到网页回执，数据刷新待核对」。「已接收，等待空闲重载」来自网页接收回执，网页仍会保护正在编辑或提交的作业。过期或归属变化的指令不会继续送达。预览后目标变化时须重新核对，回包中断后按本人原请求只读查询。

上线先应用 KV 迁移 `20261122080000_classroom_screen_management`，依次更新 KV、NPClassworks 网页和 NPEduConsole。升级时旧版无归属版本的待送达指令会作废，已收到的历史回执仍可查。原生设备撤销继续使用现有入口。隔离真库测试用 `--screen-duty-db`，Windows Console、Edge 实际大屏和原生组件联调用 `--screen-duty`，证据默认在 `.artifacts/screen-duty`。

## 教室考试模式与方案放映

从「教室设备 → 具体大屏 → 考试与放映」进入，也可从班级大屏卡直达。工作页固定显示学校、班级、屏名、绑定编号和原生设备。分别核对环境切换和方案放映状态。进入考试会联动 ClassIsland 和 ExamAware 的运行与登录自启动，先正常保存现有录制，再暂停后续自动录课，原录课计划保留。返回日常前请在教室结束 ExamAware 放映，保存并关闭未保存的编辑器内容。

选择 UTF-8 `.ea2` 或 `.json` 文件，最大 24 KiB，先投递给目标设备校验。核对设备返回的考试名称、每场起止和提醒，再点名该屏确认开播。界面分别显示设备回报切换完成、方案校验通过、启动已受理和本次放映就绪。本次就绪及结束取同一播放器会话的近期观测；观测过期时提示核对现场。尚未取得开始许可的操作可取消。回包中断先查询原请求，在当前登录会话可按原请求编号重试。从同一大屏重新进入可读服务器上的任务和设备观测。

一次返回日常成功后，上一场放映仍可在历史查到。后续只切换考试环境的教室，成功核对本轮没有投递或启动的方案后，可按独立的环境授权申请返回日常。已有开播授权时仍须核对本次会话结束，设备始终执行现场阻断检查。

上线先更新 KV，再更新 Console。沿用 NPEP 0.4/0.5 的现有授权、模式和方案数据，无新增数据库迁移。旧网页继续访问同一任务，独立原生设备撤销仍由现有入口办理。隔离验收用 `--exam-workbench-db` 和 `--exam-workbench`，后者需要构建 NPEduTools 的 ExamAware TestHost、桥接插件和本机 ExamAware 1.5.2。可用 `NP_EXAM_AWARE_SOURCE` 指定源码目录，也可用 `NP_EXAM_AWARE_ELECTRON`、`NP_EXAM_AWARE_ARCHIVE` 指定本机构建的 Electron 和归档。验收实际打开并关闭播放器，ClassIsland 登录任务、自启动及录制效果使用隔离模拟，正式打包版未覆盖。证据默认在 `.artifacts/exam-workbench/final`。

## 全校作业录入设置

在「班级与教务 → 作业录入设置」编辑本校快捷词与大屏快捷截止时间，学校尚未启用学期也可办理。快捷词支持分组排序、适用学科与换行，空表表示关闭。截止时间保留 1–8 项。试用区可切换学科试插正文，也能选基准日核对日期。基准日若也是指定星期，截止时间算到下一周的同一天。恢复默认只改当前分区的草稿。教师端与大屏刷新后读取新配置，已发布作业保留原正文和截止时间。

Console 一次保存所有已修改分区。网页的「教师分配」保存快捷词，「大屏设备」保存截止时间。两个分区各自检查版本，同一区的并发改动需要核对当前值，任何冲突都使 Console 本次提交整批零写入。失效学科引用留在草稿以便修正。回包丢失可按本校本人的原请求只读核对，再读取学校当前值。

先应用 KV 数据库迁移 `20261122090000_school_homework_settings_receipt`，发布新版 KV 后更新 NPClassworks 网页与 Console。升级中的旧缓存管理页面如果没有版本，保存会提示刷新或重新打开。教师和大屏的配置读取格式保持兼容。隔离回归用 `--homework-settings-db` 和 `--homework-settings`，证据默认在 `.artifacts/homework-settings/final`。

| --- | --- |

| 组织与班级 | Console 可维护全校学科目录，也可在当前启用学期维护年级名称与行政班、录入名单、批量补设随班授课科目并办理任课分配。可通过「年级教学安排」维护当前学期走班的来源、停用、恢复和改科。其他学期、年级代码和排序及全量授课规则仍在网页。 |
| 学生名单 | Console 可维护当前学期一个行政班的名单，支持批量粘贴、差异预览、保存及冲突核对。 |
| 教师分配 | Console 可办理班级访问分配与邮箱邀请、当前学期随班和走班任课，以及班主任和年级职责。全校快捷词见「作业录入设置」。历史学期职责和联动规则维护仍在网页。 |
| 大屏设备 | Console 可登记大屏、管理网页账号与浏览器绑定、调班、启停并核对网页值守指令。全校快捷截止时间见「作业录入设置」。 |
| 大屏互联 | Console 已覆盖部分班级接入、麦克风策略、软件维护和单台设备的考试模式与方案放映。独立设备撤销仍由网页办理。 |
| 自习监测 | Console 可维护年级与班级的日常及考试自习、监测阈值与拍照策略，核对逐屏回执及本日场次，并按权限查询照片与退出记录。教室摄像头选择和参考校准在现场办理。 |
| 自习座位表 | Console 可按自习班级预览、发布、替换、撤回、重新发布保留的历史图像并核对逐屏结果。旧网页保留原入口。 |

| 高级批量导入 | Console 可为当前或草稿学期导入年级教学组织、教师名册和普通班级访问。创建学校与归档学期仍走原入口。 |
| 服务器迁移 | 学校迁移包导出等操作仍在网页，与 KV 自动备份状态分别管理。 |
| 学期运维 | Console 可建立草稿、逐台核对和正常启用，并跟踪现场重新配对。强制启用及单独归档仍在网页。 |

教室端可在 NPEduTools 首次设置或学校互联设置中使用快速列表。目标大屏未列出时，按学校和班级的完整名称或代码查找。一个班有多台大屏时可翻页选择，随后按原流程提交申请或输入班级管理口令。精确查找需要 KV 和教室端均支持该功能。
